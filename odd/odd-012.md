# ODD-012: CRUD de Producto con catálogos sincronizados

## Objetivo

Crear la entidad `producto(id, codigo_interno, producto, precio_unitario, codigo_actividad, codigo_producto, unidad_medida)`, su CRUD completo en `partelogica` y `partevisual`, y alimentar los campos de catálogo desde las tablas generadas por la ODD-010.

La pantalla sigue el estilo de Sucursal: encabezado, modal de formulario, buscador, selector de tamaño, tabla y paginación con iconos.

## Contexto

La ODD-010 incorporó la sincronización de catálogos SIAT y, entre otras, estas tablas:

- `sincronizacion_actividad`: `codigo_caeb`, `descripcion`, `tipo_actividad`.
- `sincronizacion_producto_servicio`: `codigo_actividad`, `codigo_producto`, `descripcion_producto`.
- `sincronizacion_unidad_medida`: `codigo`, `descripcion`.

La ODD-011 estableció el patrón de CRUD con MyBatis XML, DTOs, servicio, controlador y pantalla angular con estilo Sucursal.

## Comprende

**Parte lógica:**

- Nueva tabla `producto`.
- Modelo `Producto`, DTOs y mapeador.
- `ProductoMapper` con MyBatis XML.
- `ProductoServicioGestion` y `ProductoControlador`.
- `CatalogoProductoServicio` para exponer los catálogos sincronizados.
- Consultas nuevas en `SincronizacionMapper` para actividades, productos/servicios y unidades de medida.
- Excepciones y manejo HTTP de errores.
- Documentación Swagger.

**Parte visual:**

- Opción **Producto** en el menú lateral y ruta `/producto`.
- Modelo `producto.ts` y servicio `producto.servicio.ts`.
- Pantalla `paginas/producto/producto.ts` y `producto.html` con el estilo de Sucursal.
- Formulario con `select` de actividad, producto/servicio y unidad de medida.
- Tabla con acciones **Editar** y **Borrar**.

No comprende: autenticación, autorización, auditoría, exportación, carga masiva, facturación, modificación de los WSDL ni cambios en las tablas de sincronización.

## Dependencia

Esta ODD depende de:

- ODD-008: MyBatis XML, `PaginaRespuesta`, `BotonIcono`, `Modal` y estilo Sucursal.
- ODD-010: catálogos sincronizados de actividad, producto/servicio y unidad de medida.
- ODD-011: patrón de CRUD y manejo de errores.

No se agregan dependencias Maven ni npm.

## Decisiones de esta ODD

1. `codigo_interno` es obligatorio y único.
2. `producto` es obligatorio y se recorta con `trim()`.
3. `precio_unitario` se guarda como `NUMERIC(12,2)` y se valida como mayor o igual a cero.
4. `codigo_actividad` toma su valor de `sincronizacion_actividad.codigo_caeb`.
5. `codigo_producto` toma su valor de `sincronizacion_producto_servicio.codigo_producto`.
6. `unidad_medida` toma su valor de `sincronizacion_unidad_medida.codigo`.
7. Los tres catálogos se leen de la ejecución sincronizada más reciente, usando `ejecucion_id DESC` y `id DESC` como desempate.
8. Los tres campos de catálogo se validan contra la lista vigente antes de guardar.
9. La respuesta incluye las descripciones derivadas para mostrarlas en la tabla.
10. El listado admite `busqueda`, `page` y `size`; los tamaños permitidos son `5`, `10`, `15` y `20`.

## Modelo de datos

Agregar en `basededatos/tablas.sql`:

```sql
CREATE TABLE producto (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    codigo_interno VARCHAR(50) NOT NULL,
    producto VARCHAR(250) NOT NULL,
    precio_unitario NUMERIC(12,2) NOT NULL,
    codigo_actividad VARCHAR(20) NOT NULL,
    codigo_producto BIGINT NOT NULL,
    unidad_medida INTEGER NOT NULL,
    CONSTRAINT uq_producto_codigo_interno UNIQUE (codigo_interno),
    CONSTRAINT ck_producto_precio_unitario CHECK (precio_unitario >= 0)
);
```

No se siembran productos en `basededatos/datos.sql`.

## Parte lógica

### DTOs

```java
public record ProductoSolicitud(
        @NotBlank(message = "El código interno es obligatorio.")
        @Size(max = 50, message = "El código interno no puede superar 50 caracteres.")
        String codigoInterno,

        @NotBlank(message = "El producto es obligatorio.")
        @Size(max = 250, message = "El producto no puede superar 250 caracteres.")
        String producto,

        @NotNull(message = "El precio unitario es obligatorio.")
        @DecimalMin(value = "0", message = "El precio unitario no puede ser negativo.")
        @Digits(integer = 10, fraction = 2, message = "El precio unitario no es válido.")
        BigDecimal precioUnitario,

        @NotBlank(message = "La actividad es obligatoria.")
        String codigoActividad,

        @NotNull(message = "El producto/servicio es obligatorio.")
        Long codigoProducto,

        @NotNull(message = "La unidad de medida es obligatoria.")
        Integer unidadMedida) {
}
```

```java
public record ProductoRespuesta(
        Long id,
        String codigoInterno,
        String producto,
        BigDecimal precioUnitario,
        String codigoActividad,
        String actividadDescripcion,
        Long codigoProducto,
        String productoDescripcion,
        Integer unidadMedida,
        String unidadMedidaDescripcion) {
}
```

DTOs de opciones para los select:

```java
public record ActividadOpcion(String codigo, String descripcion) { }

public record ProductoServicioOpcion(
        String codigoActividad, Long codigo, String descripcion) { }

public record UnidadMedidaOpcion(Integer codigo, String descripcion) { }
```

### Consultas de catálogo

Agregar a `SincronizacionMapper`:

```java
List<ActividadOpcion> listarActividades();

List<ProductoServicioOpcion> listarProductosServicio();

List<UnidadMedidaOpcion> listarUnidadesMedida();
```

SQL:

```sql
SELECT DISTINCT ON (codigo_caeb) codigo_caeb AS codigo, descripcion
FROM sincronizacion_actividad
WHERE descripcion IS NOT NULL
ORDER BY codigo_caeb, ejecucion_id DESC, id DESC
```

```sql
SELECT DISTINCT ON (codigo_producto)
       codigo_actividad,
       codigo_producto AS codigo,
       descripcion_producto AS descripcion
FROM sincronizacion_producto_servicio
WHERE descripcion_producto IS NOT NULL
ORDER BY codigo_producto, ejecucion_id DESC, id DESC
```

```sql
SELECT DISTINCT ON (codigo) codigo, descripcion
FROM sincronizacion_unidad_medida
WHERE descripcion IS NOT NULL
ORDER BY codigo, ejecucion_id DESC, id DESC
```

### `ProductoServicioGestion`

Métodos:

```java
PaginaRespuesta<ProductoRespuesta> listar(String busqueda, int page, int size);

ProductoRespuesta obtenerPorId(Long id);

ProductoRespuesta adicionar(ProductoSolicitud solicitud);

ProductoRespuesta modificar(Long id, ProductoSolicitud solicitud);

void eliminar(Long id);
```

Reglas:

1. `size` se valida con `5`, `10`, `15` o `20`.
2. `offset = page * size`.
3. `codigo_interno` duplicado lanza `ProductoCodigoInternoDuplicadoExcepcion` → `409`.
4. Producto inexistente lanza `ProductoNoEncontradoExcepcion` → `404`.
5. Cualquier catálogo inexistente lanza `CatalogoProductoNoValidoExcepcion` → `400`, con el campo en `problemDetail`.

### Endpoints

| Método | Ruta | Descripción | Respuesta |
| --- | --- | --- | --- |
| `GET` | `/api/v1/productos` | Lista paginada y filtrada | `200 OK` |
| `GET` | `/api/v1/productos/actividades` | Catálogo de actividades | `200 OK` |
| `GET` | `/api/v1/productos/productos-servicio` | Catálogo de productos/servicios | `200 OK` |
| `GET` | `/api/v1/productos/unidades-medida` | Catálogo de unidades de medida | `200 OK` |
| `GET` | `/api/v1/productos/{id}` | Obtiene un producto | `200 OK` / `404` |
| `POST` | `/api/v1/productos` | Adiciona un producto | `201 Created` |
| `PUT` | `/api/v1/productos/{id}` | Modifica un producto | `200 OK` |
| `DELETE` | `/api/v1/productos/{id}` | Borra un producto | `204 No Content` |

Parámetros de listado:

| Parámetro | Ejemplo | Descripción |
| --- | --- | --- |
| `busqueda` | `ingeniería` | Filtro sobre código interno, producto o descripción de catálogo |
| `page` | `0` | Página basada en cero |
| `size` | `5` | Tamaño permitido: `5`, `10`, `15` o `20` |

Ejemplo de fila:

```json
{
  "id": 1,
  "codigoInterno": "PROD-001",
  "producto": "Servicio de consultoría",
  "precioUnitario": 1250.50,

  "codigoProducto": 1004879,

```

### Manejo de errores

| Excepción | Estado HTTP | Título |
| --- | --- | --- |
| `ProductoNoEncontradoExcepcion` | `404` | Producto no encontrado |
| `ProductoCodigoInternoDuplicadoExcepcion` | `409` | Código interno de producto duplicado |
| `CatalogoProductoNoValidoExcepcion` | `400` | Catálogo de producto no válido |
| `MethodArgumentNotValidException` | `400` | Solicitud inválida |
| `IllegalArgumentException` | `400` | Solicitud inválida |

### Estructura de la pantalla

Sigue el mismo orden y estilo que `sucursal.html`:

1. Encabezado con título `Producto`, descripción `Administra los productos del sistema.` y botón **Adicionar**.
2. Modal con grilla de 12 columnas:
   - `codigoInterno`: `md:col-span-4`.
   - `producto`: `md:col-span-8`.
   - `precioUnitario`: `md:col-span-4`, `type="number"`.
   - `codigoActividad`: `md:col-span-8`, `select`.
   - `codigoProducto`: `md:col-span-6`, `select`.
   - `unidadMedida`: `md:col-span-6`, `select`.
   - Botones **Guardar** y **Cancelar**.
3. Buscador con placeholder `Buscar por código interno, producto o catálogo`.
4. Selector `Mostrar` con `5`, `10`, `15` y `20`.
5. Tabla con columnas `Código interno`, `Producto`, `Precio`, `Actividad`, `Producto/servicio`, `Unidad` y `Acciones`.
6. Acciones por fila: **Editar** y **Borrar**.
7. Pie con `Mostrando x de y` y paginación.

Comportamiento:

- Al cargar se llama a `listar('', 0, 5)` y a los tres endpoints de catálogo.
- **Adicionar** abre el formulario vacío con la primera opción de cada catálogo seleccionada.
- **Editar** carga el registro y sus códigos de catálogo.
- **Borrar** pide confirmación.
- Después de guardar o borrar se recarga la lista.
- Los errores se muestran con `error.error.detail` o el primer error de validación.
