# ODD-009: CRUD de Punto Venta, persistencia de CUIS/CUFD y acciones desde la tabla

## Objetivo

Crear la tabla `puntoventa`, su CRUD completo en `partelogica` y `partevisual`, incorporar dos tablas de historial para los datos devueltos por el SIAT al obtener CUIS y CUFD, y agregar en las acciones de la tabla de Punto Venta los botones **Obtener CUIS** y **Obtener CUFD**.

El registro vigente de cada historial se determina por `fechaVigencia`: entre las respuestas válidas y no vencidas, la de mayor vigencia queda con `estado = true` y todas las demás pasan a `false`.

## Contexto

La ODD-008 dejó funcionando:

- Persistencia con MyBatis XML.
- Empresa única con `id = 1L`.
- CRUD de `sucursal`.
- Pantalla Sucursal con buscador, paginación, tabla, formulario y botones con icono.

Las ODD-006 y ODD-007 obtienen CUIS y CUFD desde `FacturacionCodigos`, pero **no persisten** las respuestas y conservan `codigoSucursal = 0` con puntos de venta limitados a `0` y `1`.

Esta ODD incorpora el modelo `puntoventa(id, sucursal_id, codigo, puntoventa, tipo, estado)`. A partir de ella:

- `codigoSucursal` se toma de `sucursal.codigo`.
- `codigoPuntoVenta` se toma de `puntoventa.codigo`.
- El `tipo` se almacena como código numérico del `1` al `6`; por defecto es `5`.
- Cada obtención de CUIS o CUFD se guarda en una tabla de historial.
- La fila con la vigencia más reciente y aún vigente se marca como activa.

## Decisiones de esta ODD

1. `tipo` se guarda como `SMALLINT` con valores `1` a `6`; la descripción se deriva en la capa visual.
2. El valor por defecto de `tipo` es `5` en la base de datos, en el servicio y en el formulario.
3. `puntoventa.codigo` es único **dentro de una sucursal**, no global: `UNIQUE (sucursal_id, codigo)`.
4. `sucursal.codigo` y `puntoventa.codigo` deben ser numéricos porque se envían al SIAT como enteros.
5. Se agrega una sucursal semilla con `codigo = '0'` para satisfacer la llave foránea.
6. Los puntos de venta semilla tienen códigos `0` y `1`, omiten `tipo` y por tanto reciben `tipo = 5`.
7. Las tablas `cuis` y `cufd` son historial; no se siembran registros.
8. Solo una fila por `(empresa_id, puntoventa_id)` puede tener `estado = true` en cada tabla.
9. Es candidata a activa toda fila con `transaccion = true`, `fecha_vigencia` válida y mayor que `CURRENT_TIMESTAMP`.
10. Entre las candidatas gana la de mayor `fecha_vigencia`; en empate gana la de mayor `id`.
11. Una respuesta con `transaccion = false` o sin vigencia se guarda con `estado = false` y no desactiva la vigente anterior.
12. La acción **Obtener CUFD** también persiste el CUIS que el servicio obtiene internamente.
13. Los endpoints antiguos `POST /api/v1/empresas/{id}/cuis` y `/cufd` siguen existiendo y conservan su comportamiento actual.
14. Las nuevas acciones usan sobrecargas que reciben `codigoSucursal` y `codigoPuntoVenta` explícitos.
15. El SIAT puede responder `transaccion = false` con código `980` y un CUIS existente en `codigo`; `ObtenerCuisServicio` normaliza esa respuesta como `transaccion = true` para que el CUIS vigente pueda activarse.

## Modelo de datos

### `basededatos/tablas.sql`

Conservar `empresa` y `sucursal` de la ODD-008 y agregar:

```sql
CREATE TABLE puntoventa (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sucursal_id BIGINT NOT NULL REFERENCES sucursal(id),
    codigo VARCHAR(20) NOT NULL,
    puntoventa VARCHAR(250) NOT NULL,
    tipo SMALLINT NOT NULL DEFAULT 5,
    estado BOOLEAN NOT NULL DEFAULT TRUE,
    CONSTRAINT uq_puntoventa_sucursal_codigo UNIQUE (sucursal_id, codigo),
    CONSTRAINT ck_puntoventa_tipo CHECK (tipo BETWEEN 1 AND 6),
    CONSTRAINT ck_puntoventa_codigo CHECK (codigo ~ '^[0-9]+$')
);

CREATE TABLE cuis (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    empresa_id BIGINT NOT NULL REFERENCES empresa(id),
    sucursal_id BIGINT NOT NULL REFERENCES sucursal(id),
    puntoventa_id BIGINT NOT NULL REFERENCES puntoventa(id),
    codigo_sucursal INTEGER NOT NULL,
    codigo_punto_venta INTEGER NOT NULL,
    cuis VARCHAR(255) NOT NULL,
    fecha_vigencia TIMESTAMPTZ,
    transaccion BOOLEAN NOT NULL DEFAULT FALSE,
    mensajes TEXT NOT NULL DEFAULT '[]',
    estado BOOLEAN NOT NULL DEFAULT FALSE,
    fecha_obtencion TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE cufd (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    empresa_id BIGINT NOT NULL REFERENCES empresa(id),
    sucursal_id BIGINT NOT NULL REFERENCES sucursal(id),
    puntoventa_id BIGINT NOT NULL REFERENCES puntoventa(id),
    cuis_id BIGINT REFERENCES cuis(id),
    codigo_sucursal INTEGER NOT NULL,
    codigo_punto_venta INTEGER NOT NULL,
    cufd VARCHAR(255) NOT NULL,
    codigo_control VARCHAR(100),
    direccion VARCHAR(250),
    fecha_vigencia TIMESTAMPTZ,
    transaccion BOOLEAN NOT NULL DEFAULT FALSE,
    mensajes TEXT NOT NULL DEFAULT '[]',
    estado BOOLEAN NOT NULL DEFAULT FALSE,
    fecha_obtencion TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE UNIQUE INDEX ux_cuis_activo
    ON cuis (empresa_id, puntoventa_id) WHERE estado;

CREATE UNIQUE INDEX ux_cufd_activo
    ON cufd (empresa_id, puntoventa_id) WHERE estado;
```

Reglas:

1. Todos los identificadores siguen en `snake_case`.
2. `puntoventa` se crea después de `sucursal`.
3. `cuis` y `cufd` se crean después de `puntoventa`.
4. `cufd.cuis_id` permite trazar el CUIS usado en la solicitud CUFD.
5. `mensajes` guarda el JSON serializado de `CuisRespuesta.mensajes()` o `CufdRespuesta.mensajes()`.
6. El token de la empresa nunca se persiste en estas tablas.

`partelogica/src/main/resources/mapper/PuntoVentaMapper.xml`:

```xml
<mapper namespace="bo.org.citior.sife.mapper.PuntoVentaMapper">

  <sql id="filtro">
    <if test="busqueda != null and busqueda != ''">
      AND (LOWER(pv.codigo) LIKE LOWER(CONCAT('%', #{busqueda}, '%'))
        OR LOWER(pv.puntoventa) LIKE LOWER(CONCAT('%', #{busqueda}, '%'))
        OR LOWER(s.codigo) LIKE LOWER(CONCAT('%', #{busqueda}, '%')))
    </if>
  </sql>

  <select id="findById" resultType="bo.org.citior.sife.dominio.PuntoVenta">
    SELECT pv.id, pv.sucursal_id, pv.codigo, pv.puntoventa, pv.tipo, pv.estado
    FROM puntoventa pv
    WHERE pv.id = #{id}
  </select>

  <select id="listar" resultType="bo.org.citior.sife.dominio.PuntoVenta">
    SELECT pv.id, pv.sucursal_id, pv.codigo, pv.puntoventa, pv.tipo, pv.estado
    FROM puntoventa pv
    JOIN sucursal s ON s.id = pv.sucursal_id
    WHERE 1 = 1
    <include refid="filtro" />
    ORDER BY pv.sucursal_id, pv.codigo::integer, pv.id
    LIMIT #{size} OFFSET #{offset}
  </select>

  <select id="contar" resultType="long">
    SELECT COUNT(*)
    FROM puntoventa pv
    JOIN sucursal s ON s.id = pv.sucursal_id
    WHERE 1 = 1
    <include refid="filtro" />
  </select>

  <select id="existsBySucursalIdAndCodigo" resultType="boolean">
    SELECT EXISTS (
      SELECT 1 FROM puntoventa
      WHERE sucursal_id = #{sucursalId} AND codigo = #{codigo}
    )
  </select>

  <select id="existsBySucursalIdAndCodigoAndIdNot" resultType="boolean">
    SELECT EXISTS (
      SELECT 1 FROM puntoventa
      WHERE sucursal_id = #{sucursalId}
        AND codigo = #{codigo}
        AND id <> #{id}
    )
  </select>

  <insert id="insert"
          parameterType="bo.org.citior.sife.dominio.PuntoVenta"
          useGeneratedKeys="true"
          keyProperty="id">
    INSERT INTO puntoventa (sucursal_id, codigo, puntoventa, tipo, estado)
    VALUES (#{sucursalId}, #{codigo}, #{puntoventa}, #{tipo}, #{estado})
  </insert>

  <update id="update" parameterType="bo.org.citior.sife.dominio.PuntoVenta">
    UPDATE puntoventa
    SET sucursal_id = #{sucursalId},
        codigo = #{codigo},
        puntoventa = #{puntoventa},
        tipo = #{tipo},
        estado = #{estado}
    WHERE id = #{id}
  </update>

  <delete id="delete">
    DELETE FROM puntoventa WHERE id = #{id}
  </delete>

</mapper>
```

`codigo::integer` es seguro porque la restricción `ck_puntoventa_codigo` garantiza valores numéricos.

### 5. Crear `PuntoVentaServicio`

Métodos:

```java
PaginaRespuesta<PuntoVentaRespuesta> listar(String busqueda, int page, int size);

PuntoVentaRespuesta obtenerPorId(Long id);

PuntoVentaRespuesta adicionar(PuntoVentaSolicitud solicitud);

PuntoVentaRespuesta modificar(Long id, PuntoVentaSolicitud solicitud);

void eliminar(Long id);

PuntoVenta obtenerModelo(Long id);
```

Reglas:

1. La búsqueda aplica `LIKE %texto%` a `puntoventa.codigo`, `puntoventa.puntoventa` y `sucursal.codigo`, sin distinguir mayúsculas.
2. `offset = page * size`.
3. `size` se valida en el controlador: solo `5`, `10`, `15` o `20`.
4. Si `tipo` llega `null`, se usa `TipoPuntoVenta.porDefecto().getCodigo()` (`5`).
5. Si `tipo` está fuera de `1..6`, se rechaza con `400`.
6. La sucursal indicada debe existir; si no, se lanza `SucursalNoEncontradaExcepcion` → `404`.
7. El código no puede repetirse dentro de la misma sucursal; si se repite, se lanza `PuntoVentaCodigoDuplicadoExcepcion` → `409`.
8. Un punto de venta inexistente lanza `PuntoVentaNoEncontradoExcepcion` → `404`.
9. `obtenerModelo` se usa desde los servicios de CUIS/CUFD; no expone datos en la API.
10. Toda la persistencia se realiza con `PuntoVentaMapper` y su XML.

<mapper namespace="bo.org.citior.sife.mapper.CuisMapper">

  <insert id="insert"
          parameterType="bo.org.citior.sife.dominio.Cuis"
          useGeneratedKeys="true"
          keyProperty="id">
    INSERT INTO cuis (
        empresa_id, sucursal_id, puntoventa_id, codigo_sucursal,
        codigo_punto_venta, cuis, fecha_vigencia, transaccion, mensajes, estado
    ) VALUES (
        #{empresaId}, #{sucursalId}, #{puntoventaId}, #{codigoSucursal},
        #{codigoPuntoVenta}, #{cuis}, #{fechaVigencia}, #{transaccion}, #{mensajes}, FALSE
    )
  </insert>

  <update id="activarVigente">
    WITH candidato AS (
      SELECT id
      FROM cuis
      WHERE empresa_id = #{empresaId}
        AND puntoventa_id = #{puntoventaId}
        AND transaccion = TRUE
        AND fecha_vigencia IS NOT NULL
        AND fecha_vigencia > CURRENT_TIMESTAMP
      ORDER BY fecha_vigencia DESC, id DESC
      LIMIT 1
    )
    UPDATE cuis
    SET estado = (id IN (SELECT id FROM candidato))
    WHERE empresa_id = #{empresaId}
      AND puntoventa_id = #{puntoventaId}
  </update>

</mapper>

### 8. Registro de CUIS y selección del vigente

`RegistroCuisServicio`:

```java
Long registrar(CuisRespuesta respuesta, PuntoVenta puntoVenta);
```

Pasos:

1. Si `ObtenerCuisServicio` recibió código `980` con `codigo` no vacío, usar `transaccion = true` en la respuesta normalizada.
2. Convertir `respuesta.fechaVigencia()` con `OffsetDateTime.parse(...).toInstant()`.
3. Si la conversión falla o el valor es nulo, guardar `fecha_vigencia = NULL`.
4. Serializar `respuesta.mensajes()` a JSON con `ObjectMapper`.
5. Insertar la fila con `estado = FALSE`.
6. Llamar a `CuisMapper.activarVigente(1L, puntoVenta.getId())`.
7. Devolver el `id` insertado.

La conversión de fecha no lanza excepción hacia el cliente: una vigencia inválida solo impide que la fila sea candidata a activa.

### 9. Registro de CUFD y selección del vigente

`RegistroCufdServicio`:

```java
Long registrar(CufdRespuesta respuesta, PuntoVenta puntoVenta, Long cuisId);
```

Pasos idénticos a CUIS, guardando además `cuis_id` y llamando a `CufdMapper.activarVigente(1L, puntoVenta.getId())`.

### 10. Sobrecargas de los servicios SIAT

En `ObtenerCuisServicio` agregar:

```java
public CuisRespuesta obtener(Long empresaId, int codigoSucursal, int codigoPuntoVenta);
```

El método existente `obtener(Long, CuisSolicitud)` delega con `codigoSucursal = 0` y `solicitud.codigoPuntoVenta()`.

En `ObtenerCufdServicio` agregar:

```java
public CufdRespuesta obtener(Long empresaId, int codigoSucursal, int codigoPuntoVenta);

public CufdRespuesta obtenerConCuis(Long empresaId, int codigoSucursal,
                                    int codigoPuntoVenta, CuisRespuesta cuisRespuesta);
```

El método `obtener(Long, CufdSolicitud)` conserva su comportamiento actual: obtiene internamente el CUIS con sucursal `0`.

`obtenerConCuis` no invoca `ObtenerCuisServicio`; usa el CUIS recibido y evita una segunda llamada SOAP.

### 11. Orquestación de las acciones CUIS/CUFD

En `PuntoVentaControlador`:

```java
@PostMapping("/{id}/cuis")
public ResponseEntity<CuisRespuesta> obtenerCuis(@PathVariable Long id);

@PostMapping("/{id}/cufd")
public ResponseEntity<CufdRespuesta> obtenerCufd(@PathVariable Long id);
```

Flujo de **Obtener CUIS**:

1. Obtener `PuntoVenta` con `PuntoVentaServicio.obtenerModelo(id)`.
2. Obtener su `Sucursal` con `SucursalMapper.findById`.
3. Convertir `sucursal.codigo` y `puntoventa.codigo` a `int`.
4. Si alguno no es numérico, lanzar `ConfiguracionSiatInvalidaExcepcion` → `409`.
5. Llamar a `ObtenerCuisServicio.obtener(1L, codigoSucursal, codigoPuntoVenta)`.
6. Registrar con `RegistroCuisServicio`.
7. Devolver `CuisRespuesta` con `200 OK`.

Flujo de **Obtener CUFD**:

1. Repetir los pasos 1 a 4.
2. Llamar a `ObtenerCuisServicio.obtener(1L, codigoSucursal, codigoPuntoVenta)`.
3. Registrar ese CUIS con `RegistroCuisServicio` y capturar su `id`.
4. Llamar a `ObtenerCufdServicio.obtenerConCuis(1L, codigoSucursal, codigoPuntoVenta, cuisRespuesta)`.
5. Registrar el CUFD con `RegistroCufdServicio`, pasando el `cuisId`.
6. Devolver `CufdRespuesta` con `200 OK`.

Todos los pasos de cada acción ocurren en una sola transacción `@Transactional`.
