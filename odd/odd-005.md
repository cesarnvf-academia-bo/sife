# ODD-005: Clientes Apache CXF para los servicios SIAT y verificación de comunicación

## Objetivo

Incorporar Apache CXF en `partelogica` para consumir los cuatro servicios SOAP del SIAT, enviando el token de la empresa en la cabecera HTTP `apiKey` con el formato `TokenApi <token>`, y exponer una operación `verificarComunicacion` desde el paquete `bo.org.citior.sife.controlador`.

## Contexto

La ODD-004 dejó disponible la tabla `empresa` y las operaciones básicas sobre ella. El token de acceso al SIAT se almacena en la columna `empresa.token` y debe utilizarse en cada solicitud a los servicios de facturación.

Los servicios del SIAT para el ambiente piloto son:

| Servicio | WSDL | Dirección SOAP |
| --- | --- | --- |
| Facturación Sincronización | `https://pilotosiatservicios.impuestos.gob.bo/v2/FacturacionSincronizacion?wsdl` | `https://pilotosiatservicios.impuestos.gob.bo/v2/FacturacionSincronizacion` |
| Facturación Operaciones | `https://pilotosiatservicios.impuestos.gob.bo/v2/FacturacionOperaciones?wsdl` | `https://pilotosiatservicios.impuestos.gob.bo/v2/FacturacionOperaciones` |
| Facturación Códigos | `https://pilotosiatservicios.impuestos.gob.bo/v2/FacturacionCodigos?wsdl` | `https://pilotosiatservicios.impuestos.gob.bo/v2/FacturacionCodigos` |
| Facturación Compraventa | `https://pilotosiatservicios.impuestos.gob.bo/v2/ServicioFacturacionCompraVenta?wsdl` | `https://pilotosiatservicios.impuestos.gob.bo/v2/ServicioFacturacionCompraVenta` |

La cuarta ruta se toma con el sufijo correcto `?wsdl`; en la solicitud original figuraba `?wsd`.

Cada uno de los cuatro servicios expone la operación `verificarComunicacion`, que no recibe parámetros y devuelve una respuesta con la indicación de transacción y la lista de mensajes del SIAT.

La autenticación del SIAT se realiza mediante la cabecera HTTP:

```http
apiKey: TokenApi <token>
```

No debe agregarse dentro del XML SOAP. El valor se construye con el prefijo `TokenApi`, un espacio y el token obtenido de `empresa.token`.

## Comprende

- Dependencias de Apache CXF y del generador de clientes.
- Copia local de los WSDL y de sus WSDL importados.
- Generación de clientes JAX-WS en el paquete base `bo.gob.impuesto.siat`.
- Fábrica de clientes SOAP con tiempos de conexión y respuesta.
- Interceptor que agrega la cabecera HTTP `apiKey`.
- Lectura del token desde la tabla `empresa`.
- Servicio que consulta `verificarComunicacion` en los cuatro servicios.
- Controlador REST `VerificarComunicacionControlador` en `bo.org.citior.sife.controlador`.
- Manejo del error de token no configurado.
- Pruebas del interceptor y del controlador.

No comprende: implementar las demás operaciones del SIAT (CUIS, CUFD, sincronización de catálogos, registro de puntos de venta, recepción de facturas, anulación, etc.), persistir respuestas del SIAT, modificar el frontend ni administrar tokens desde la interfaz.

### 5. Crear el interceptor de la cabecera `apiKey`

Crear `InterceptorTokenApi`:

```java
public class InterceptorTokenApi extends AbstractPhaseInterceptor<Message> {

    private final String token;

    public InterceptorTokenApi(String token) {
        super(Phase.PRE_PROTOCOL);
        this.token = token;
    }

    @Override
    @SuppressWarnings("unchecked")
    public void handleMessage(Message mensaje) {
        Map<String, List<String>> cabeceras =
                (Map<String, List<String>>) mensaje.get(MessageContext.HTTP_REQUEST_HEADERS);

        if (cabeceras == null) {
            cabeceras = new HashMap<>();
            mensaje.put(MessageContext.HTTP_REQUEST_HEADERS, cabeceras);
        }

        cabeceras.put("apiKey", List.of("TokenApi " + token.trim()));
    }
}
```

El interceptor se agrega a la cadena de salida del cliente. No se debe registrar el token en logs.

### 6. Crear la fábrica de clientes SOAP

Crear `ClienteSiatFactory`:

```java
@Component
@RequiredArgsConstructor
public class ClienteSiatFactory {

    private final Bus busCxf;
    private final PropiedadesSiat propiedades;

    public <T> T crearPuerto(Class<T> interfaz, String url, String token) {
        JaxWsProxyFactoryBean fabrica = new JaxWsProxyFactoryBean();
        fabrica.setBus(busCxf);
        fabrica.setServiceClass(interfaz);
        fabrica.setAddress(url);

        T puerto = interfaz.cast(fabrica.create());
        Client cliente = ClientProxy.getClient(puerto);

        cliente.getOutInterceptors().add(new InterceptorTokenApi(token));
        configurarTiempos(cliente);

        return puerto;
    }

    private void configurarTiempos(Client cliente) {
        HTTPConduit conducto = (HTTPConduit) cliente.getConduit();
        HTTPClientPolicy politica = conducto.getClient();

        if (politica == null) {
            politica = new HTTPClientPolicy();
            conducto.setClient(politica);
        }

        politica.setConnectionTimeout(propiedades.tiempoConexionMs());
        politica.setReceiveTimeout(propiedades.tiempoRespuestaMs());
    }
}
```

La dirección debe ser la URL del servicio sin `?wsdl`. El WSDL solo se usa para generar el cliente.

### 7. Crear el servicio de verificación

Crear `VerificarComunicacionServicio`:

```java
@Service
@RequiredArgsConstructor
public class VerificarComunicacionServicio {

    private final EmpresaRepositorio empresaRepositorio;
    private final ClienteSiatFactory clienteSiatFactory;
    private final PropiedadesSiat propiedades;

    public RespuestaVerificacionComunicacion verificar(Long empresaId) {
        Empresa empresa = empresaRepositorio.findById(empresaId)
                .orElseThrow(() -> new EmpresaNoEncontradaExcepcion(empresaId));

        if (empresa.getToken() == null || empresa.getToken().isBlank()) {
            throw new TokenSiatNoConfiguradoExcepcion(empresaId);
        }

        String token = empresa.getToken().trim();
        List<ResultadoServicioSiat> resultados = List.of(
                verificarCodigos(token),
                verificarSincronizacion(token),
                verificarOperaciones(token),
                verificarCompraventa(token));

        return new RespuestaVerificacionComunicacion(
                empresa.getId(),
                empresa.getNit(),
                Instant.now(),
                resultados);
    }
}
```

Cada método privado debe:

1. Crear el puerto con `clienteSiatFactory.crearPuerto(...)`.
2. Invocar `verificarComunicacion()`.
3. Leer `isTransaccion()` y la lista `getMensajesList()`.
4. Devolver un `ResultadoServicioSiat` con el nombre del servicio, el estado, el primer código disponible y la descripción de los mensajes.
5. Capturar cualquier excepción del servicio y devolver `comunicacion = false` con el mensaje de error, sin interrumpir la verificación de los demás servicios.

No se debe mantener una transacción de base de datos abierta mientras se ejecutan las llamadas SOAP. `findById` del repositorio es suficiente para obtener el token.

### 9. Crear el controlador en el paquete solicitado

Crear `VerificarComunicacionControlador` en `bo.org.citior.sife.controlador`:

```java
@RestController
@RequestMapping("/api/v1/empresas/{id}/verificar-comunicacion")
@RequiredArgsConstructor
@Tag(name = "Verificación SIAT", description = "Verificación de comunicación con los servicios SIAT")
public class VerificarComunicacionControlador {

    private final VerificarComunicacionServicio verificarComunicacionServicio;

    @GetMapping
    @Operation(
            summary = "Verificar comunicación",
            description = "Verifica la comunicación con los cuatro servicios SIAT usando el token de la empresa.")
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Verificación realizada"),
            @ApiResponse(responseCode = "404", description = "Empresa no encontrada"),
            @ApiResponse(responseCode = "409", description = "Token SIAT no configurado")
    })
    public ResponseEntity<RespuestaVerificacionComunicacion> verificar(@PathVariable Long id) {
        return ResponseEntity.ok(verificarComunicacionServicio.verificar(id));
    }
}
```

### 10. Manejar el token no configurado

Crear `TokenSiatNoConfiguradoExcepcion`:

```java
public class TokenSiatNoConfiguradoExcepcion extends RuntimeException {

    private final Long empresaId;

    public TokenSiatNoConfiguradoExcepcion(Long empresaId) {
        super("La empresa " + empresaId + " no tiene token SIAT configurado.");
        this.empresaId = empresaId;
    }

    public Long getEmpresaId() {
        return empresaId;
    }
}
```

Agregar el manejador en `ManejadorErrores`:

```java
@ExceptionHandler(TokenSiatNoConfiguradoExcepcion.class)
public ProblemDetail manejarTokenNoConfigurado(TokenSiatNoConfiguradoExcepcion excepcion) {
    ProblemDetail problema = ProblemDetail.forStatusAndDetail(
            HttpStatus.CONFLICT, excepcion.getMessage());
    problema.setTitle("Token SIAT no configurado");
    problema.setProperty("empresaId", excepcion.getEmpresaId());
    return problema;
}
```

### 11. Consideraciones de seguridad

- El token se lee de `empresa.token` y solo se envía en la cabecera HTTP.
- El token no debe incluirse en respuestas, logs, trazas ni mensajes de error.
- No se debe desactivar la validación TLS. Los servicios son HTTPS y usan el almacén de confianza de la JVM.
- Si el certificado del SIAT no está en el almacén por defecto, configurar un `trustStore` explícito; nunca usar `TrustAll`.
- La cabecera debe ser exactamente `apiKey: TokenApi <token>`.
- La cabecera va en la petición HTTP, no en el encabezado SOAP del XML.

## Criterios de Aceptación

- [ ] Apache CXF `4.2.4` está agregado en `pom.xml`.

- [ ] Una empresa inexistente responde `404`.
