# ODD-007: Obtención del CUFD desde el servicio Facturación Códigos

## Objetivo

Implementar en `partelogica` la operación que obtiene el CUFD de una empresa desde el servicio SOAP `FacturacionCodigos` del SIAT, enviando siempre `codigoSucursal = 0` y permitiendo únicamente los puntos de venta `0` y `1`.

## Contexto

La ODD-005 incorporó Apache CXF, la fábrica de clientes SOAP `ClienteSiatFactory`, el interceptor `InterceptorTokenApi` y el cliente generado `ServicioFacturacionCodigos`.

La ODD-006 incorporó la obtención del CUIS mediante `ObtenerCuisServicio`, con `codigoSucursal = 0` y puntos de venta `0` y `1`. Esta ODD reutiliza ese servicio para obtener el CUIS que exige la operación `cufd`.

La operación `cufd` del WSDL recibe un objeto `solicitudCufd` con estos campos:

| Campo | Tipo | Origen |
| --- | --- | --- |
| `codigoAmbiente` | `int` | `empresa.ambiente` |
| `codigoModalidad` | `int` | `empresa.modalidad` |
| `codigoPuntoVenta` | `int` nullable | Solicitud REST; solo `0` o `1` |
| `codigoSistema` | `string` | `empresa.codigoSistema` |
| `codigoSucursal` | `int` | Fijo en `0` |
| `cuis` | `string` | CUIS obtenido para el mismo punto de venta |
| `nit` | `long` | `empresa.nit` |

El WSDL marca `codigoPuntoVenta` como opcional y lo genera como `JAXBElement<Integer>`. En esta ODD será obligatorio y se enviará mediante `ObjectFactory.createSolicitudCufdCodigoPuntoVenta(...)`.

La respuesta `respuestaCufd` contiene:

| Campo | Uso |
| --- | --- |
| `codigo` | CUFD obtenido |
| `codigoControl` | Código de control del CUFD |
| `direccion` | Dirección devuelta por el SIAT |
| `fechaVigencia` | Fecha y hora de vigencia |
| `mensajesList` | Mensajes del SIAT |
| `transaccion` | Indica si la operación fue exitosa |

## Comprende

- DTO de solicitud `CufdSolicitud`.
- DTO de respuesta `CufdRespuesta`.
- Servicio `ObtenerCufdServicio`.
- Controlador REST `CufdControlador`.
- Obtención interna del CUIS mediante `ObtenerCuisServicio`.
- Manejo de errores con las excepciones existentes de la ODD-006.
- Pruebas del controlador y del servicio.
- Documentación Swagger del endpoint.

No comprende: persistencia del CUFD, CUIS masivo, CUFD masivo, sincronización de catálogos, registro de puntos de venta, emisión de facturas, modificación de la tabla `empresa` ni cambios en el frontend.

## Contrato del endpoint

| Método | Ruta | Descripción |
| --- | --- | --- |
| `POST` | `/api/v1/empresas/{id}/cufd` | Obtiene el CUFD para el punto de venta indicado |

Solicitud:

```json
{
  "codigoPuntoVenta": 0
}
```

`codigoPuntoVenta` es obligatorio y solo acepta `0` o `1`. `codigoSucursal` no se recibe desde el cliente: el servicio siempre envía `0`.

El cliente no envía el CUIS. El servicio obtiene un CUIS para la misma sucursal y punto de venta mediante `ObtenerCuisServicio`, y luego lo utiliza en la solicitud del CUFD.

Para obtener el CUFD de ambos puntos de venta se invoca el endpoint dos veces, una con `0` y otra con `1`.

Respuesta exitosa:

```json
{
  "empresaId": 1,
  "nit": "710035027",
  "codigoSucursal": 0,
  "codigoPuntoVenta": 0,
  "cufd": "A1B2C3D4E5F6...",
  "codigoControl": "ABC123DEF456",
  "direccion": "LA PAZ",
  "fechaVigencia": "2026-11-17T23:59:59.000-04:00",
  "transaccion": true,
  "mensajes": [
    {
      "codigo": 926,
      "descripcion": "COMUNICACION EXITOSA"
    }
  ]
}
```

`cufd` se obtiene de `RespuestaCufd.getCodigo()`.

Estados HTTP:

| Estado | Situación |
| --- | --- |
| `200` | El SIAT respondió, aunque `transaccion` sea `false` |
| `400` | `codigoPuntoVenta` ausente o fuera de `0` y `1` |
| `404` | La empresa no existe |
| `409` | La empresa no tiene token o su configuración SIAT es inválida |
| `502` | No se pudo obtener el CUIS o falló la invocación del CUFD |

## Implementación

### 1. Reutilizar el cliente de Facturación Códigos

No se agregan dependencias ni WSDL. Se usa la interfaz generada:

```java
bo.gob.impuesto.siat.codigos.ServicioFacturacionCodigos
```

La operación generada es:

```java
RespuestaCufd cufd(SolicitudCufd solicitudCufd);
```

El puerto se crea con `ClienteSiatFactory.crearPuerto(...)`, usando `propiedades.codigosUrl()` y el token de la empresa. La cabecera `apiKey: TokenApi <token>` la agrega automáticamente `InterceptorTokenApi`.

### 2. Crear el DTO de solicitud

Crear `CufdSolicitud`:

```java
public record CufdSolicitud(
        @NotNull(message = "El punto de venta es obligatorio.")
        @Min(value = 0, message = "El punto de venta debe ser 0 o 1.")
        @Max(value = 1, message = "El punto de venta debe ser 0 o 1.")
        Integer codigoPuntoVenta) {
}
```

El controlador debe usar `@Valid` para que `ManejadorErrores` transforme las violaciones en `400 Bad Request`.

### 3. Crear el DTO de respuesta

Crear `CufdRespuesta`:

```java
public record CufdRespuesta(
        Long empresaId,
        String nit,
        int codigoSucursal,
        int codigoPuntoVenta,
        String cufd,
        String codigoControl,
        String direccion,
        String fechaVigencia,
        boolean transaccion,
        List<MensajeCufd> mensajes) {

    public record MensajeCufd(Integer codigo, String descripcion) {
    }
}
```

`fechaVigencia` se obtiene con `XMLGregorianCalendar.toXMLFormat()`. No se realizan conversiones de zona horaria.

### 4. Crear el servicio

Crear `ObtenerCufdServicio`:

```java
@Service
@RequiredArgsConstructor
public class ObtenerCufdServicio {

    private static final int CODIGO_SUCURSAL = 0;

    private final EmpresaRepositorio empresaRepositorio;
    private final ObtenerCuisServicio obtenerCuisServicio;
    private final ClienteSiatFactory clienteSiatFactory;
    private final PropiedadesSiat propiedades;

    public CufdRespuesta obtener(Long empresaId, CufdSolicitud solicitud) {
        Empresa empresa = empresaRepositorio.findById(empresaId)
                .orElseThrow(() -> new EmpresaNoEncontradaExcepcion(empresaId));

        if (empresa.getToken() == null || empresa.getToken().isBlank()) {
            throw new TokenSiatNoConfiguradoExcepcion(empresaId);
        }

        String codigoSistema = empresa.getCodigoSistema();
        if (codigoSistema == null || codigoSistema.isBlank()) {
            throw new ConfiguracionSiatInvalidaExcepcion(empresaId, "codigoSistema");
        }

        int codigoAmbiente = parsearEntero(
                empresaId, "ambiente", empresa.getAmbiente());
        int codigoModalidad = parsearEntero(
                empresaId, "modalidad", empresa.getModalidad());
        long nit = parsearNit(empresaId, empresa.getNit());
        int codigoPuntoVenta = solicitud.codigoPuntoVenta();

        CuisRespuesta cuisRespuesta = obtenerCuisServicio.obtener(
                empresaId, new CuisSolicitud(codigoPuntoVenta));

        String cuis = cuisRespuesta.cuis();
        if (!cuisRespuesta.transaccion() || cuis == null || cuis.isBlank()) {
            throw new SiatNoDisponibleExcepcion(
                    "FacturacionCodigos",
                    "No se obtuvo un CUIS válido para el punto de venta "
                            + codigoPuntoVenta + ".");
        }

        SolicitudCufd solicitudSiat = new SolicitudCufd();
        solicitudSiat.setCodigoAmbiente(codigoAmbiente);
        solicitudSiat.setCodigoModalidad(codigoModalidad);
        solicitudSiat.setCodigoSistema(codigoSistema);
        solicitudSiat.setCodigoSucursal(CODIGO_SUCURSAL);
        solicitudSiat.setCuis(cuis);
        solicitudSiat.setNit(nit);
        solicitudSiat.setCodigoPuntoVenta(new ObjectFactory()
                .createSolicitudCufdCodigoPuntoVenta(codigoPuntoVenta));

        try {
            RespuestaCufd respuesta = clienteSiatFactory
                    .crearPuerto(
                            ServicioFacturacionCodigos.class,
                            propiedades.codigosUrl(),
                            empresa.getToken().trim())
                    .cufd(solicitudSiat);

            return new CufdRespuesta(
                    empresa.getId(),
                    empresa.getNit(),
                    CODIGO_SUCURSAL,
                    codigoPuntoVenta,
                    respuesta.getCodigo(),
                    respuesta.getCodigoControl(),
                    respuesta.getDireccion(),
                    respuesta.getFechaVigencia() == null
                            ? null
                            : respuesta.getFechaVigencia().toXMLFormat(),
                    Boolean.TRUE.equals(respuesta.isTransaccion()),
                    respuesta.getMensajesList().stream()
                            .map(mensaje -> new CufdRespuesta.MensajeCufd(
                                    mensaje.getCodigo(),
                                    mensaje.getDescripcion()))
                            .toList());
        } catch (Exception excepcion) {
            throw new SiatNoDisponibleExcepcion(
                    "FacturacionCodigos", mensajeError(excepcion));
        }
    }

    private int parsearEntero(Long empresaId, String campo, String valor) {
        try {
            return Integer.parseInt(valor);
        } catch (NumberFormatException excepcion) {
            throw new ConfiguracionSiatInvalidaExcepcion(empresaId, campo);
        }
    }

    private long parsearNit(Long empresaId, String nit) {
        try {
            return Long.parseLong(nit);
        } catch (NumberFormatException excepcion) {
            throw new ConfiguracionSiatInvalidaExcepcion(empresaId, "nit");
        }
    }

    private String mensajeError(Exception excepcion) {
        String mensaje = excepcion.getMessage();
        return mensaje == null || mensaje.isBlank()
                ? excepcion.getClass().getSimpleName()
                : mensaje;
    }
}
```

Reglas del servicio:

1. Buscar la empresa por `id`.
2. Rechazar empresas sin token.
3. Validar `codigoSistema`, `nit`, `ambiente` y `modalidad`.
4. Obtener el CUIS para el mismo `codigoPuntoVenta` mediante `ObtenerCuisServicio`.
5. Rechazar la operación si el CUIS no fue obtenido o está vacío.
6. Enviar siempre `codigoSucursal = 0`.
7. Enviar el `codigoPuntoVenta` recibido, que ya fue validado como `0` o `1`.
8. Enviar el CUIS obtenido en el campo `cuis`.
9. Mapear `RespuestaCufd` al DTO de respuesta.
10. No persistir el CUFD ni abrir transacciones de base de datos durante las llamadas SOAP.

### 5. Crear el controlador

Crear `CufdControlador` en `bo.org.citior.sife.controlador`:

```java
@RestController
@RequestMapping("/api/v1/empresas/{id}/cufd")
@RequiredArgsConstructor
@Tag(name = "CUFD", description = "Obtención del CUFD desde el SIAT")
public class CufdControlador {

    private final ObtenerCufdServicio obtenerCufdServicio;

    @PostMapping
    @Operation(
            summary = "Obtener CUFD",
            description = "Obtiene el CUFD para la sucursal 0 y el punto de venta indicado. "
                    + "Obtiene internamente el CUIS requerido.")
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Respuesta del SIAT"),
            @ApiResponse(responseCode = "400", description = "Punto de venta inválido"),
            @ApiResponse(responseCode = "404", description = "Empresa no encontrada"),
            @ApiResponse(responseCode = "409", description = "Token o configuración SIAT inválida"),
            @ApiResponse(responseCode = "502", description = "No se pudo obtener el CUIS o el CUFD")
    })
    public ResponseEntity<CufdRespuesta> obtener(
            @PathVariable Long id,
            @Valid @RequestBody CufdSolicitud solicitud) {

        return ResponseEntity.ok(obtenerCufdServicio.obtener(id, solicitud));
    }
}
```

### 6. Manejo de errores

No se crean excepciones nuevas. Se reutilizan las de la ODD-006:

- `EmpresaNoEncontradaExcepcion` responde `404`.
- `TokenSiatNoConfiguradoExcepcion` responde `409`.
- `ConfiguracionSiatInvalidaExcepcion` responde `409`.
- `SiatNoDisponibleExcepcion` responde `502`.
- `MethodArgumentNotValidException` responde `400`.

Si `ObtenerCuisServicio` no obtiene un CUIS válido, `ObtenerCufdServicio` lanza `SiatNoDisponibleExcepcion` y no invoca la operación `cufd`.

## Criterios de Aceptación

- [ ] El endpoint `POST /api/v1/empresas/{id}/cufd` está disponible.
- [ ] El servicio envía siempre `codigoSucursal = 0`.
- [ ] Solo se aceptan los puntos de venta `0` y `1`.
- [ ] Un punto de venta inválido responde `400`.
- [ ] El CUIS se obtiene para la misma sucursal y punto de venta.
- [ ] El CUIS obtenido se envía en la solicitud `cufd`.
- [ ] `codigoAmbiente`, `codigoModalidad`, `codigoSistema` y `nit` se toman de la empresa.
- [ ] El token se envía mediante la cabecera `apiKey: TokenApi <token>`.
- [ ] La respuesta incluye `cufd`, `codigoControl`, `direccion`, `fechaVigencia`, `transaccion` y `mensajes`.
- [ ] Una empresa inexistente responde `404`.
- [ ] Una empresa sin token o con configuración inválida responde `409`.
- [ ] Un fallo al obtener el CUIS o al invocar el CUFD responde `502`.
- [ ] El token no aparece en respuestas ni logs.
- [ ] La compilación y las pruebas finalizan sin errores.

## Confirmación y cierre

La ODD se considera completada cuando:

- El endpoint obtiene el CUFD desde `FacturacionCodigos`.
- La solicitud envía `codigoSucursal = 0`.
- Los únicos puntos de venta aceptados son `0` y `1`.
- El CUIS se obtiene para el mismo punto de venta y se usa en la solicitud del CUFD.
- Los datos de la empresa se envían correctamente.
- Los errores `400`, `404`, `409` y `502` están cubiertos.
- El token no se expone.
- La compilación y las pruebas pasan.
- El responsable técnico revisa y aprueba el entregable, dejando constancia del cierre de la ODD-007.
