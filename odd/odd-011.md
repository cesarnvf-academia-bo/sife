# ODD-011: CRUD de Cliente y catálogo de Tipo de documento de identidad

## Objetivo

Crear la entidad `cliente(id, codigo_interno, cliente, dit, tipo, correo)`, su CRUD completo en `partelogica` y `partevisual`, y utilizar en el formulario un selector de `tipo` alimentado por el catálogo `sincronizacion_tipo_documento_identidad` de la ODD-010.

La pantalla sigue el estilo de Sucursal: encabezado, modal de formulario, buscador, selector de tamaño, tabla, pie con `Mostrando` y paginación con iconos.

## Contexto

La ODD-008 dejó funcionando la persistencia con MyBatis XML y el CRUD de `sucursal`. La ODD-009 agregó `puntoventa`, CUIS/CUFD y la tabla de puntos de venta. La ODD-010 incorporó la sincronización de catálogos SIAT, entre ellos `sincronizacion_tipo_documento_identidad`.

El campo `tipo` de `cliente` no se codifica como constante en la parte visual: se obtiene desde la API, que lee el catálogo sincronizado. Cuando aún no existe una sincronización, la API devuelve la lista semántica definida en esta ODD para que el selector nunca quede vacío.

## Comprende

**Parte lógica:**

- Nueva tabla `cliente`.
- Modelo `Cliente`, DTOs `ClienteSolicitud`, `ClienteRespuesta` y `TipoDocumentoIdentidadRespuesta`.
- `ClienteMapper` con MyBatis XML.
- `ClienteServicio`, `TipoDocumentoIdentidadServicio` y `ClienteControlador`.
- Excepciones `ClienteNoEncontradoExcepcion`, `ClienteCodigoInternoDuplicadoExcepcion` y `TipoDocumentoIdentidadNoValidoExcepcion`.
- Endpoints CRUD y endpoint del catálogo de tipos de documento de identidad.
- Documentación Swagger y manejo HTTP de errores.

**Parte visual:**

- Opción **Cliente** en el menú lateral y ruta `/cliente`.
- Modelo `cliente.ts` y servicio `cliente.servicio.ts`.
- Pantalla `paginas/cliente/cliente.ts` y `cliente.html` con el estilo de Sucursal.
- Formulario con `codigoInterno`, `cliente`, `dit`, `tipo` como `select` y `correo`.
- Tabla con `Cod. interno`, `Cliente`, `DIT`, `Tipo`, `Correo` y `Acciones`.
- Botones **Editar** y **Borrar** por fila, con confirmación para borrar.

No comprende: autenticación, autorización, auditoría, exportación, carga masiva, facturación, modificación de los WSDL, cambios en el catálogo SIAT ni persistencia de nuevos tipos de documento.

## Dependencia

Esta ODD depende de:

- ODD-008: MyBatis XML, `PaginaRespuesta`, `BotonIcono`, `Modal` y pantalla Sucursal.
- ODD-010: tabla `sincronizacion_tipo_documento_identidad` y `SincronizacionMapper`.

No se agregan dependencias Maven ni npm.

## Decisiones de esta ODD

1. `dit` se conserva literalmente como nombre del campo y de la columna.
2. `cliente`, `dit` y `correo` son obligatorios y se recortan con `trim()`.
3. `correo` se valida con formato de correo electrónico.
4. `tipo` es obligatorio y debe existir en el catálogo de tipos de documento de identidad.
5. El catálogo se lee de `sincronizacion_tipo_documento_identidad`, tomando el valor más reciente por `codigo` según `ejecucion_id` descendente.
6. Se parte de la lista definida en esta ODD y se sobreescriben las descripciones de los códigos `1..5` cuando la tabla sincronizada las contiene.
7. No se agrega campo `estado` a `cliente`, porque no forma parte del modelo solicitado.
8. No se agrega validación de `dit` duplicado, porque no fue requerido.
9. `tipoDescripcion` se deriva en la parte lógica para mostrar el texto en la tabla.
10. El listado admite `busqueda`, `page` y `size`; los tamaños permitidos son `5`, `10`, `15` y `20`.
11. `codigo_interno` es obligatorio, se recorta con `trim()` y es único en toda la tabla.

## Catálogo de Tipo de documento de identidad

Contenido definido:

| Código | Descripción |
| --- | --- |
| `1` | CI - CEDULA DE IDENTIDAD |
| `2` | CEX - CEDULA DE IDENTIDAD DE EXTRANJERO |
| `3` | PAS - PASAPORTE |
| `4` | OD - OTRO DOCUMENTO DE IDENTIDAD |
| `5` | NIT - NÚMERO DE IDENTIFICACIÓN TRIBUTARIA |

```json
[
  { "codigo": 1, "descripcion": "CI - CEDULA DE IDENTIDAD" },

  { "codigo": 5, "descripcion": "NIT - NÚMERO DE IDENTIFICACIÓN TRIBUTARIA" }

```

## Modelo de datos

Agregar en `basededatos/tablas.sql`:

```sql
CREATE TABLE cliente (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    codigo_interno VARCHAR(50) NOT NULL,
    cliente VARCHAR(250) NOT NULL,
    dit VARCHAR(50) NOT NULL,
    tipo INTEGER NOT NULL,
    correo VARCHAR(250) NOT NULL,
    CONSTRAINT uq_cliente_codigo_interno UNIQUE (codigo_interno),
    CONSTRAINT ck_cliente_tipo CHECK (tipo BETWEEN 1 AND 5)
);
```

No se agregan filas en `basededatos/datos.sql`.

### `ClienteMapper`

Métodos:

```java
Cliente findById(@Param("id") Long id);

List<Cliente> listar(
        @Param("busqueda") String busqueda,
        @Param("offset") int offset,
        @Param("size") int size);

long contar(@Param("busqueda") String busqueda);

void insert(Cliente cliente);

void update(Cliente cliente);

void delete(@Param("id") Long id);

boolean existsByCodigoInterno(String codigoInterno);

boolean existsByCodigoInternoAndIdNot(
        @Param("codigoInterno") String codigoInterno,
        @Param("id") Long id);
```

`ClienteMapper.xml` filtra con `LIKE %texto%` sobre `codigo_interno`, `cliente`, `dit` y `correo`, ordena por `id` y aplica `LIMIT`/`OFFSET`.

### `TipoDocumentoIdentidadServicio`

Métodos:

```java
List<TipoDocumentoIdentidadRespuesta> listar();

String descripcion(Integer codigo);

boolean existe(Integer codigo);
```

Consulta agregada a `SincronizacionMapper`:

```java
List<TipoDocumentoIdentidadRespuesta> listarTiposDocumentoIdentidad();
```

SQL:

```sql
SELECT DISTINCT ON (codigo) codigo, descripcion
FROM sincronizacion_tipo_documento_identidad
WHERE descripcion IS NOT NULL
ORDER BY codigo, ejecucion_id DESC, id DESC
```

La respuesta siempre contiene los cinco códigos definidos en este documento; las descripciones de la tabla sincronizada reemplazan a las predeterminadas cuando existen para esos códigos.

### `ClienteServicio`

Métodos:

```java
PaginaRespuesta<ClienteRespuesta> listar(String busqueda, int page, int size);

ClienteRespuesta obtenerPorId(Long id);

ClienteRespuesta adicionar(ClienteSolicitud solicitud);

ClienteRespuesta modificar(Long id, ClienteSolicitud solicitud);

void eliminar(Long id);
```

Reglas:

1. `size` se valida con `5`, `10`, `15` o `20`.
2. `offset = page * size`.
3. Un `tipo` inexistente lanza `TipoDocumentoIdentidadNoValidoExcepcion` → `400`.
4. Un cliente inexistente lanza `ClienteNoEncontradoExcepcion` → `404`.
5. `tipoDescripcion` se obtiene de `TipoDocumentoIdentidadServicio.descripcion(...)`.
6. Un `codigo_interno` repetido lanza `ClienteCodigoInternoDuplicadoExcepcion` → `409`, tanto al adicionar como al modificar.

### Endpoints

| Método | Ruta | Descripción | Respuesta |
| --- | --- | --- | --- |
| `GET` | `/api/v1/clientes` | Lista paginada y filtrada | `200 OK` |
| `GET` | `/api/v1/clientes/tipos-documento-identidad` | Lista el catálogo de tipos | `200 OK` |
| `GET` | `/api/v1/clientes/{id}` | Obtiene un cliente | `200 OK` / `404` |
| `POST` | `/api/v1/clientes` | Adiciona un cliente | `201 Created` / `409` |
| `PUT` | `/api/v1/clientes/{id}` | Modifica un cliente | `200 OK` / `409` |
| `DELETE` | `/api/v1/clientes/{id}` | Borra un cliente | `204 No Content` |

Parámetros de listado:

| Parámetro | Ejemplo | Descripción |
| --- | --- | --- |
| `busqueda` | `NIT` | Filtro sobre código interno, cliente, DIT o correo |
| `page` | `0` | Página basada en cero |
| `size` | `5` | Tamaño permitido: `5`, `10`, `15` o `20` |

Ejemplo de fila:

```json
{
  "id": 1,
  "codigoInterno": "CLI-001",
  "cliente": "Distribuidora Central",
  "dit": "1234567",
  "tipo": 5,
  "tipoDescripcion": "NIT - NÚMERO DE IDENTIFICACIÓN TRIBUTARIA",
  "correo": "contacto@example.com"
}
```

### Manejo de errores

| Excepción | Estado HTTP | Título |
| --- | --- | --- |
| `ClienteNoEncontradoExcepcion` | `404` | Cliente no encontrado |
| `ClienteCodigoInternoDuplicadoExcepcion` | `409` | Código interno de cliente duplicado |
| `TipoDocumentoIdentidadNoValidoExcepcion` | `400` | Tipo de documento de identidad no válido |
| `MethodArgumentNotValidException` | `400` | Solicitud inválida |
| `IllegalArgumentException` | `400` | Solicitud inválida |

### Estructura de la pantalla

Sigue el mismo orden y estilo que `sucursal.html`:

1. Encabezado con título `Cliente`, descripción `Administra los clientes del sistema.` y botón **Adicionar**.
 2. Modal con grilla de 12 columnas:
   - `codigoInterno`: `md:col-span-4`.
   - `cliente`: `md:col-span-8`.
   - `dit`: `md:col-span-6`.
   - `tipo`: `md:col-span-6`, `select` con las opciones devueltas por la API.
   - `correo`: `md:col-span-12`, `type="email"`.
   - Botones **Guardar** y **Cancelar**.
 3. Buscador con placeholder `Buscar por código interno, cliente, DIT o correo`.
 4. Selector `Mostrar` con `5`, `10`, `15` y `20`.
 5. Tabla con columnas `Cod. interno`, `Cliente`, `DIT`, `Tipo`, `Correo` y `Acciones`.
6. Acciones por fila: **Editar** y **Borrar**.
7. Pie con `Mostrando x de y` y paginación.

Comportamiento:

- Al cargar se llama a `listar('', 0, 5)` y a `listarTiposDocumentoIdentidad()`.
- **Adicionar** abre el formulario vacío con el primer tipo seleccionado.
- **Editar** carga el registro y su `tipo`.
- **Borrar** pide confirmación.
- Después de guardar o borrar se recarga la lista.
- Los errores se muestran con `error.error.detail` o el primer error de validación.

## Criterios de Aceptación

**Base de datos:**

- [ ] Existe `cliente(id, codigo_interno, cliente, dit, tipo, correo)`.
- [ ] `codigo_interno` es único.
- [ ] `tipo` acepta solo `1..5`.
- [ ] No se siembran clientes.

**Parte lógica:**

- [ ] Existen los cinco endpoints CRUD.
- [ ] Existe `GET /api/v1/clientes/tipos-documento-identidad`.
- [ ] El catálogo se lee desde `sincronizacion_tipo_documento_identidad`.
- [ ] Siempre se devuelven los cinco tipos de esta ODD, con descripciones actualizadas desde la tabla cuando existen.
- [ ] `tipo` inexistente responde `400`.
- [ ] Código interno duplicado responde `409`.
- [ ] Cliente inexistente responde `404`.
- [ ] El listado admite `busqueda`, `page` y `size`.
- [ ] Solo se permiten tamaños `5`, `10`, `15` y `20`.
- [ ] Swagger documenta todos los endpoints.

- [ ] El estilo coincide con la pantalla Sucursal.
- [ ] El formulario muestra `codigoInterno` y `tipo` como `select` con los cinco tipos.

- [ ] La aplicación compila sin errores.



3. Compilar la parte lógica:

   ```bash
   cd ../partelogica
   ./mvnw clean verify
   ```

   ```bash

     -H 'Content-Type: application/json' \
   ```
