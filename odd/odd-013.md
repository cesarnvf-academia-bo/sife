# ODD-013: Facturación electrónica Compra Venta

## Objetivo

Analizar y formalizar la estructura para emitir una factura electrónica de Compra Venta:

1. Definir la estructura de `facturaElectronicaCompraVenta.xml` y `facturaElectronicaCompraVenta.xsd`.
2. Crear dos tablas: `factura` y `detalle`.
3. Persistir todos los campos de cabecera del XML y los campos de respuesta del servicio SOAP `ServicioFacturacionCompraVenta`.
4. Dejar el modelo preparado para **anular** y **revertir anulación** de facturas.
5. Generar el CUF, construir el XML, firmarlo digitalmente, comprimirlo con gzip y enviarlo por SOAP.
6. Documentar la generación de `generarfirma/sife.p12` con clave `123qwe` en `generarfirma/README.md`.

## Decisiones de esta ODD

1. Los archivos de referencia se mantienen en `recursos/`; esta ODD documenta su estructura y no los reemplaza.
2. El elemento raíz del XML es `facturaElectronicaCompraVenta`.
3. La secuencia del XML es `cabecera`, `detalle` (de 1 a 500) y `ds:Signature`.
4. El campo `complemento` y los opcionales se envían con `xsi:nil="true"` cuando no tienen valor.
5. `codigoDocumentoSector` se fija en `1` para Compra Venta.
6. Se crean únicamente dos tablas de negocio: `factura` y `detalle`.
7. Los mensajes del SIAT se guardan como `JSONB` en la factura; no se crea una tercera tabla.
8. `factura.cuf` es único.
9. El estado de la factura usa `EMITIDA`, `ANULADA`, `REVERTIDA` y `RECHAZADA`.
10. Anular y revertir no eliminan filas: actualizan el estado y guardan la respuesta del SIAT.
11. El CUF se genera con los 53 dígitos definidos, más un dígito Módulo 11, Base 16 y el `codigoControl` del CUFD vigente.
12. El XML se valida contra el XSD antes de firmarse.
13. La firma se inserta como `ds:Signature` después del último `detalle`.
14. El archivo firmado se comprime con gzip y se envía en Base64 en `archivo`.
15. `hashArchivo` es el SHA-256 del archivo gzip generado.
16. La clave del PKCS#12 para desarrollo es `123qwe`; el archivo `sife.p12` no debe versionarse.
17. `ruta_firma_digital` y `clave_firma_digital` se leen desde `empresa`.

## Generación del CUF

### Campos de la cadena

| Orden | Campo | Longitud | Observación |
| --- | --- | --- | --- |
| 1 | NIT emisor | 13 | Cerosa a la izquierda. |
| 2 | Fecha/hora emisión | 17 | `yyyyMMddHHmmssSSS`. |
| 3 | Sucursal | 4 | `0` para casa matriz. |
| 4 | Modalidad | 1 | `1`, `2` o `3`. |
| 5 | Tipo de emisión | 1 | `1` Online, `2` Offline, `3` Masiva. |
| 6 | Tipo factura/documento ajuste | 1 | `1`, `2` o `3`. |
| 7 | Tipo documento sector | 2 | `01` para Compra Venta. |
| 8 | Número de factura | 10 | Cerosa a la izquierda. |
| 9 | Punto de venta | 4 | `0000` si no corresponde. |
|  | **Total antes del verificador** | **53** |  |
| 10 | Dígito Módulo 11 | 1 | Se agrega al final. |
|  | **Total de la cadena decimal** | **54** |  |

### Algoritmo

1. Completar cada campo con ceros a la izquierda según su longitud.
2. Concatenar los 9 campos en el orden indicado.
3. Calcular el dígito verificador con Módulo 11:
   - Recorrer los 53 dígitos de derecha a izquierda.
   - Aplicar pesos `2, 3, 4, 5, 6, 7, 8, 9` de forma cíclica.
   - `digito = suma % 11`; si el resultado es `10`, usar `1`.
4. Concatenar el dígito a la cadena de 53 dígitos.
5. Convertir la cadena decimal de 54 dígitos a Base 16 mayúscula usando `BigInteger`.
6. Concatenar el `codigoControl` obtenido en `cufd`/`solicitudCufd`.

Ejemplo documentado:

```text
Cadena 53 dígitos:
00001234567892019011316372123100001110100000000010000

Con verificador Módulo 11:
000012345678920190113163721231000011101000000000100001

Base 16:
8727F63A15F8976591FDDE5B387C5D015A29E06A1

Con código de control A19E23EF34124CD:
8727F63A15F8976591FDDE5B387C5D015A29E06A1A19E23EF34124CD
```

Pseudocódigo Java:

```java
String cadena53 = String.format(
        "%013d%017d%04d%01d%01d%01d%02d%010d%04d",
        nitEmisor, fechaHora, codigoSucursal, codigoModalidad,
        codigoEmision, tipoFacturaDocumento, codigoDocumentoSector,
        numeroFactura, codigoPuntoVenta);

int digito = calcularModulo11(cadena53);
String cadena54 = cadena53 + digito;
String base16 = new BigInteger(cadena54).toString(16).toUpperCase(Locale.ROOT);
String cuf = base16 + cufd.getCodigoControl();
```

## Flujo de emisión

1. Validar empresa, sucursal, punto de venta, CUIS y CUFD vigentes.
2. Validar que cada `codigoProductoSin` y `unidadMedida` exista en los catálogos sincronizados vigentes.
3. Calcular `subTotal` por detalle y totales de cabecera.
4. Generar `cuf` con el algoritmo descrito.
5. Construir el XML con `cabecera`, `detalle` y valores `xsi:nil` donde corresponda.
6. Validar el XML contra `facturaElectronicaCompraVenta.xsd`.
7. Firmar el XML con `generarfirma/sife.p12` y clave `123qwe`.
8. Insertar `ds:Signature` después del último `detalle`.
9. Comprimir el XML firmado con gzip.
10. Calcular `hashArchivo = SHA-256(gzip)` y `fechaEnvio` en hora local de Bolivia (`America/La_Paz`) sin zona horaria y con tres decimales.
11. Convertir el gzip a Base64 y llamar a `recepcionFactura`.
12. Persistir `factura`, `detalle`, respuesta, mensajes y estado.
13. Si `transaccion` es `false`, marcar estado `RECHAZADA` y conservar los mensajes.

## Flujo de anulación

1. Buscar la factura por `id` y verificar que esté `EMITIDA`.
2. Obtener CUIS y CUFD vigentes.
3. Llamar a `anulacionFactura` con `cuf` y `codigoMotivo`.
4. Guardar fecha, motivo, transacción, código de estado, descripción y mensajes.
5. Si `transaccion` es `true`, cambiar el estado a `ANULADA`.

## Flujo de reversión

1. Buscar la factura por `id` y verificar que esté `ANULADA`.
2. Obtener CUIS y CUFD vigentes.
3. Llamar a `reversionAnulacionFactura` con `cuf`.
4. Guardar fecha, transacción, código de estado, descripción y mensajes.
5. Si `transaccion` es `true`, cambiar el estado a `REVERTIDA`.
