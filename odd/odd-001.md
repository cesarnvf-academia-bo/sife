# ODD-001: Estructura base de la parte lógica con controlador de ping

## Objetivo

Crear la estructura inicial del proyecto `partelogica` utilizando Java 25, Spring Boot 4 y Swagger (OpenAPI), aplicando una arquitectura por capas y código limpio con nomenclatura en español. El resultado debe exponer un controlador de ping que permita verificar que la aplicación se encuentra activa y correctamente documentada.

## Contexto

El sistema SIFE requiere una base técnica uniforme sobre la cual construir los módulos posteriores. La carpeta `partelogica` será el punto de partida del backend. Por ello se necesita un esqueleto compilable, ejecutable y verificable, con separación clara de responsabilidades, configuración de documentación interactiva y un endpoint mínimo de salud (`ping`) que sirva como primera validación de la cadena completa: controlador, servicio, configuración y documentación.

## Comprende

- Creación del proyecto `partelogica` con Maven y Java 25.
- Configuración de Spring Boot 4 como framework base.
- Organización del código bajo arquitectura por capas:
  - **Presentación:** controladores REST.
  - **Aplicación/Servicio:** lógica de negocio.
  - **Dominio:** modelos y contratos de respuesta.
  - **Infraestructura/Configuración:** configuración de Swagger y propiedades.
- Implementación de un controlador de ping.
- Documentación automática de la API con Swagger/OpenAPI.
- Nomenclatura, paquetes, clases, métodos y variables en español.
- Pruebas automatizadas mínimas para el endpoint de ping.

No comprende: autenticación, persistencia en base de datos, reglas de negocio de módulos funcionales, despliegue en servidores ni integración con servicios externos.

Proyecto `partelogica` con la siguiente estructura propuesta:

└── src

    │   │   ├── servicio

    │   │   ├── dominio
    │   │   │   └── RespuestaPing.java
    │   │   └── configuracion

    │       └── application.yml

        └── java/bo/org/citior/sife/controlador

Contrato del endpoint:

```text
GET /api/v1/ping
```

Respuesta esperada (`200 OK`):

```json
{
  "estado": "activo",
  "mensaje": "pong",
  "marcaDeTiempo": "2026-01-01T00:00:00Z"
}
```

Documentación interactiva disponible en:

```text
/swagger-ui/index.html
/v3/api-docs
```

## Implementación

1. **Crear el proyecto Maven** en la carpeta `partelogica` con `groupId` `bo.org.citior`, `artifactId` `sife` y Java 25.
2. **Configurar `pom.xml`** con las dependencias:
   - `spring-boot-starter-web`
   - `spring-boot-starter-validation`
   - `springdoc-openapi-starter-webmvc-ui` (versión compatible con Spring Boot 4)
   - `spring-boot-starter-test` (alcance de pruebas)
3. **Configurar `application.yml`** con nombre de aplicación, puerto y ruta base de la API.
4. **Crear la clase principal** `SifeApplication` con `@SpringBootApplication`.
5. **Crear el modelo de dominio** `RespuestaPing` como `record` con los campos `estado`, `mensaje` y `marcaDeTiempo`.
6. **Crear la capa de servicio** `PingServicio` con el método `obtenerRespuesta()`, encargado de construir la respuesta. El controlador no debe contener lógica de negocio.
7. **Crear la capa de presentación** `PingControlador` con la anotación `@RestController`, ruta base `/api/v1/ping` y método `responderPing()` que delegue en `PingServicio`.
8. **Documentar el endpoint** con anotaciones de OpenAPI (`@Operation`, `@ApiResponse`) y configurar el título, descripción y versión mediante `ConfiguracionOpenApi`.
9. **Aplicar código limpio y nomenclatura en español**:
   - Métodos: `responderPing`, `obtenerRespuesta`, `encontrarPorIdentificador`, en lugar de `findById`.
   - Clases y paquetes: `controlador`, `servicio`, `dominio`, `configuracion`.
   - Sin abreviaturas innecesarias ni comentarios obvios.
10. **Crear la prueba** `PingControladorPrueba` con `@WebMvcTest` para validar el código de estado, el tipo de contenido y el cuerpo de la respuesta.
11. **Verificar la compilación y ejecución** con Maven y acceder a Swagger UI.

Fragmento de referencia del controlador:

```java
package bo.org.citior.sife.controlador;

import bo.org.citior.sife.dominio.RespuestaPing;
import bo.org.citior.sife.servicio.PingServicio;
import io.swagger.v3.oas.annotations.Operation;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/v1/ping")
public class PingControlador {

    private final PingServicio pingServicio;

    public PingControlador(PingServicio pingServicio) {
        this.pingServicio = pingServicio;
    }

    @GetMapping
    @Operation(summary = "Verificar disponibilidad", description = "Confirma que el servicio se encuentra activo.")
    public ResponseEntity<RespuestaPing> responderPing() {
        return ResponseEntity.ok(pingServicio.obtenerRespuesta());
    }
}
```

## Criterios de Aceptación

- [ ] La carpeta `partelogica` contiene un proyecto Maven compilable con Java 25.
- [ ] El proyecto utiliza Spring Boot 4 y arranca sin errores.
- [ ] La estructura respeta la arquitectura por capas: presentación, servicio, dominio y configuración.
- [ ] El endpoint `GET /api/v1/ping` responde `200 OK` con el contrato definido.
- [ ] El controlador delega la construcción de la respuesta en la capa de servicio.
- [ ] Swagger UI es accesible y muestra documentado el endpoint de ping.
- [ ] Los nombres de paquetes, clases, métodos y variables están en español.
- [ ] No existen comentarios innecesarios ni lógica de negocio en los controladores.
- [ ] La prueba automatizada del controlador de ping se ejecuta correctamente.
- [ ] La compilación y las pruebas finalizan sin errores ni advertencias críticas.

## Verificación

1. Compilar y ejecutar las pruebas:

   ```bash
   ./mvnw clean verify
   ```

2. Iniciar la aplicación:

   ```bash
   ./mvnw spring-boot:run
   ```

3. Verificar el endpoint de ping:

   ```bash
   curl -i http://localhost:8080/api/v1/ping
   ```

   Se debe recibir `200 OK` y el cuerpo JSON con los campos `estado`, `mensaje` y `marcaDeTiempo`.

4. Verificar la documentación OpenAPI:

   ```bash
   curl -i http://localhost:8080/v3/api-docs
   ```

5. Abrir en el navegador:

   ```text
   http://localhost:8080/swagger-ui/index.html
   ```

   Se debe visualizar el endpoint `GET /api/v1/ping` con su descripción y esquema de respuesta.

6. Revisar la estructura de carpetas y confirmar la separación de capas.

## Confirmación y cierre

La ODD se considera completada cuando:

- Todos los criterios de aceptación están marcados como cumplidos.
- La ejecución de `./mvnw clean verify` finaliza correctamente.
- El endpoint de ping y Swagger UI fueron verificados con las evidencias correspondientes (salida de comandos y captura de la documentación).
- La estructura de `partelogica` queda disponible como base para las siguientes iteraciones del sistema SIFE.
- El responsable técnico revisa y aprueba el entregable, dejando constancia del cierre de la ODD-001.
