# ODD-004: Funciones de empresa en la parte lógica y opción Empresa en la parte visual

## Objetivo

Implementar en `partelogica` las funciones `adicionar`, `modificar` y `obtenerPorId` sobre la tabla `empresa`, utilizando Lombok en el modelo, y agregar en `partevisual` la opción **Empresa** dentro del menú, implementada como un componente que permita consultar y actualizar los datos de una empresa.

## Contexto

Las ODD-001, ODD-002 y ODD-003 dejaron disponibles la estructura base de la parte lógica, la base de datos con la tabla `empresa` y el layout de la parte visual con Angular 22 y Tailwind CSS 4. La presente ODD integra ambas partes mediante una API REST para la gestión básica de empresas y una pantalla de actualización en el frontend.

La tabla `empresa` ya existe y contiene las columnas: `id`, `nit`, `razonsocial`, `codigoSistema`, `modalidad`, `ambiente`, `rutacodigo`, `rutasincronizacion`, `rutaoperacion`, `rutacompraventa`, `token`, `rutafirmadigital` y `clavefirmadigital`.

## Comprende

**Parte lógica:**

- Entidad JPA `Empresa` con Lombok.
- Repositorio `EmpresaRepositorio`.
- DTO `EmpresaSolicitud` y `EmpresaRespuesta`.
- Mapeador `EmpresaMapeador`.
- Servicio `EmpresaServicio` con los métodos `adicionar`, `modificar` y `obtenerPorId`.
- Controlador REST `EmpresaControlador`.
- Manejo de errores y validaciones.
- Configuración de PostgreSQL y JPA.
- Documentación con Swagger.

**Parte visual:**

- Opción **Empresa** en la barra lateral.
- Componente `Empresa` para la actualización de datos.
- Servicio HTTP `EmpresaServicio`.
- Formulario reactivo con las operaciones de consultar, adicionar, modificar y limpiar.
- Botones con iconos.
- Migas de pan con la ruta `Inicio > Empresa`.
- Configuración del proxy hacia la API.

No comprende: eliminación de empresas, listado o paginación, autenticación, carga de archivos, gestión de usuarios ni otros módulos.

## Implementación

### Parte lógica

1. **Agregar dependencias** en `pom.xml`:
   - `spring-boot-starter-data-jpa`.
   - `org.postgresql:postgresql` con alcance `runtime`.
   - `org.projectlombok:lombok` versión `1.18.48` con alcance opcional.

2. **Configurar la conexión** en `application.yml`:

   ```yaml
   spring:
     datasource:
       url: ${BD_URL:jdbc:postgresql://localhost:5432/sife}
       username: ${BD_USUARIO:postgres}
       password: ${BD_CLAVE:}
     jpa:
       open-in-view: false
       hibernate:
         ddl-auto: none
       properties:
         hibernate:
           globally_quoted_identifiers: true
   ```

   La propiedad `globally_quoted_identifiers` es necesaria para respetar las columnas `codigoSistema`, `rutacodigo`, `rutasincronizacion`, `rutaoperacion`, `rutacompraventa`, `rutafirmadigital` y `clavefirmadigital`, creadas entre comillas en PostgreSQL.

3. **Crear la entidad `Empresa`** con Lombok. No usar `@Data` en entidades JPA; usar `@Getter`, `@Setter`, `@Builder`, `@NoArgsConstructor` y `@AllArgsConstructor`.

   ```java
   @Entity
   @Table(name = "empresa")
   @Getter
   @Setter
   @Builder
   @NoArgsConstructor
   @AllArgsConstructor
   public class Empresa {

       @Id
       @GeneratedValue(strategy = GenerationType.IDENTITY)
       private Long id;

       @Column(name = "nit", length = 20)
       private String nit;

       @Column(name = "razonsocial", length = 250)
       private String razonsocial;

       @Column(name = "codigoSistema", length = 50)
       private String codigoSistema;

       @Column(name = "modalidad", length = 50)
       private String modalidad;

       @Column(name = "ambiente", length = 50)
       private String ambiente;

       @Column(name = "rutacodigo")
       private String rutaCodigo;

       @Column(name = "rutasincronizacion")
       private String rutaSincronizacion;

       @Column(name = "rutaoperacion")
       private String rutaOperacion;

       @Column(name = "rutacompraventa")
       private String rutaCompraventa;

       @Column(name = "token")
       private String token;

       @Column(name = "rutafirmadigital")
       private String rutaFirmaDigital;

       @Column(name = "clavefirmadigital")
       private String claveFirmaDigital;
   }
   ```

4. **Crear el repositorio** `EmpresaRepositorio`:

   ```java
   public interface EmpresaRepositorio extends JpaRepository<Empresa, Long> {
   }
   ```

5. **Crear los DTO**:
   - `EmpresaSolicitud`: datos de entrada con validaciones `@NotBlank`, `@Size`.
   - `EmpresaRespuesta`: datos de salida sin exponer `token` ni `claveFirmaDigital`; incluir `tieneToken` y `tieneClaveFirmaDigital`.

6. **Crear el mapeador** `EmpresaMapeador` con:
   - `aEntidad(EmpresaSolicitud solicitud)`.
   - `actualizar(Empresa empresa, EmpresaSolicitud solicitud)`.
   - `aRespuesta(Empresa empresa)`.

   En la modificación, si `token` o `claveFirmaDigital` llegan nulos o vacíos, se conserva el valor existente.

7. **Crear el servicio** `EmpresaServicio` con Lombok `@RequiredArgsConstructor` y los métodos:

   ```java
   @Transactional
   public EmpresaRespuesta adicionar(EmpresaSolicitud solicitud);

   @Transactional
   public EmpresaRespuesta modificar(Long id, EmpresaSolicitud solicitud);

   @Transactional(readOnly = true)
   public EmpresaRespuesta obtenerPorId(Long id);
   ```

   Si la empresa no existe, lanzar `EmpresaNoEncontradaExcepcion`.

8. **Crear el controlador** `EmpresaControlador` con ruta base `/api/v1/empresas`, anotaciones de Swagger y los tres endpoints definidos.

9. **Crear el manejo de errores** con `@RestControllerAdvice`:
   - `EmpresaNoEncontradaExcepcion` → `404 Not Found`.
   - Errores de validación → `400 Bad Request`.

10. **Documentar** los endpoints con `@Tag`, `@Operation` y `@ApiResponse`.

11. **Verificar** la compilación y las pruebas con Maven.

### Parte visual

12. **Agregar la opción Empresa** al menú en `barra-lateral.ts`:

    ```ts
    { etiqueta: 'Empresa', ruta: '/empresa', icono: 'empresas' }
    ```

13. **Agregar la ruta** en `app.routes.ts`:

    ```ts
    {
      path: 'empresa',
      loadComponent: () => import('./paginas/empresa/empresa').then((modulo) => modulo.Empresa),
      data: { miga: 'Empresa' }
    }
    ```

14. **Actualizar `MigasPan`** para anteponer la miga `Inicio` cuando la ruta actual no sea `Inicio`, de modo que se visualice `Inicio > Empresa`.

15. **Crear los modelos** `Empresa` y `EmpresaSolicitud` en `modelos/empresa.ts` con los mismos nombres de campo usados por la API.

16. **Crear el servicio HTTP** `EmpresaServicio` con:

    ```ts
    obtenerPorId(id: number) { ... }
    adicionar(solicitud: EmpresaSolicitud) { ... }
    modificar(id: number, solicitud: EmpresaSolicitud) { ... }
    ```

17. **Habilitar `provideHttpClient()`** en `app.config.ts`.

18. **Configurar el proxy** en `proxy.conf.json` para dirigir `/api` a `http://localhost:8080` y registrarlo en `angular.json` en la configuración de `serve`.

19. **Crear el componente `Empresa`** en `paginas/empresa/empresa.ts` y `empresa.html`, con formulario reactivo y las acciones:
    - **Buscar:** carga una empresa por `id`.
    - **Adicionar:** crea una empresa.
    - **Modificar:** actualiza la empresa cargada.
    - **Limpiar:** restablece el formulario.

20. **Usar el componente reutilizable `BotonIcono`** en todas las acciones y agregar los iconos `buscar`, `agregar`, `actualizar` y `limpiar` al registro de `icono.ts`.

21. **Mostrar estados** de carga, éxito y error en la pantalla.

22. **No mostrar** los valores actuales de `token` ni `claveFirmaDigital`; los campos se muestran vacíos y solo se actualizan si se ingresan nuevos valores.

23. **Verificar** la compilación y la navegación en la aplicación.

## Criterios de Aceptación

**Parte lógica:**

- [ ] La entidad `Empresa` utiliza Lombok y está mapeada a la tabla `empresa`.
- [ ] El repositorio `EmpresaRepositorio` extiende `JpaRepository`.
- [ ] El servicio expone `adicionar`, `modificar` y `obtenerPorId`.
- [ ] `POST /api/v1/empresas` crea una empresa y responde `201 Created`.
- [ ] `PUT /api/v1/empresas/{id}` actualiza una empresa y responde `200 OK`.
- [ ] `GET /api/v1/empresas/{id}` obtiene una empresa y responde `200 OK`.
- [ ] Una empresa inexistente responde `404 Not Found`.
- [ ] Los datos inválidos responden `400 Bad Request`.
- [ ] La respuesta no expone `token` ni `claveFirmaDigital`.
- [ ] Swagger documenta los tres endpoints.
- [ ] La compilación y las pruebas finalizan sin errores.

**Parte visual:**

- [ ] La barra lateral muestra la opción **Empresa** con icono.
- [ ] La opción **Empresa** navega a `/#/empresa`.
- [ ] La pantalla Empresa es un componente independiente y cargado por ruta.
- [ ] El componente permite buscar, adicionar, modificar y limpiar.
- [ ] Todos los botones de la pantalla tienen icono.
- [ ] Las migas de pan muestran `Inicio > Empresa`.
- [ ] La aplicación compila sin errores.

## Verificación

1. Recrear la base de datos y compilar la parte lógica:

   ```bash
   cd basededatos
   bash inicializar.sh
   cd ../partelogica
   ./mvnw clean verify
   ```

2. Iniciar la parte lógica:

   ```bash
   ./mvnw spring-boot:run
   ```

3. Verificar la creación de una empresa:

   ```bash
   curl -i -X POST http://localhost:8080/api/v1/empresas \
     -H 'Content-Type: application/json' \
     -d '{"nit":"123456789","razonsocial":"Empresa de Prueba SRL","codigoSistema":"SIFE","modalidad":"ELECTRONICA","ambiente":"PRODUCCION","rutaCodigo":"/rutas/codigo","rutaSincronizacion":"/rutas/sincronizacion","rutaOperacion":"/rutas/operacion","rutaCompraventa":"/rutas/compraventa","token":"token-de-acceso","rutaFirmaDigital":"/rutas/firma","claveFirmaDigital":"clave-de-firma"}'
   ```

4. Verificar la obtención por identificador:

   ```bash
   curl -i http://localhost:8080/api/v1/empresas/1
   ```

5. Verificar la modificación:

   ```bash
   curl -i -X PUT http://localhost:8080/api/v1/empresas/1 \
     -H 'Content-Type: application/json' \
     -d '{"nit":"123456789","razonsocial":"Empresa Actualizada SRL","codigoSistema":"SIFE","modalidad":"ELECTRONICA","ambiente":"PRODUCCION","rutaCodigo":"/rutas/codigo","rutaSincronizacion":"/rutas/sincronizacion","rutaOperacion":"/rutas/operacion","rutaCompraventa":"/rutas/compraventa","rutaFirmaDigital":"/rutas/firma"}'
   ```

6. Verificar los casos de error:
   - `GET /api/v1/empresas/9999` debe responder `404`.
   - `POST` con `nit` vacío debe responder `400`.

7. Verificar Swagger en `http://localhost:8080/swagger-ui/index.html`.

8. Compilar y ejecutar la parte visual:

   ```bash
   cd partevisual
   npm install
   npm run build
   npm run start
   ```

9. Abrir `http://localhost:4200/#/empresa` y verificar:
   - La opción Empresa aparece en el menú.
   - Las migas de pan muestran `Inicio > Empresa`.
   - La búsqueda por identificador carga los datos.
   - La modificación guarda los cambios.
   - La creación de una nueva empresa funciona.
   - Todos los botones muestran icono.

10. Confirmar en la base de datos que los cambios fueron persistidos:

    ```bash
    psql -U postgres -d sife -c 'SELECT id, nit, razonsocial FROM empresa;'
    ```
