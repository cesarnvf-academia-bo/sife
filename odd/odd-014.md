# ODD-014: Notificación por correo de facturas aprobadas

## Objetivo

Integrar JavaMail, Thymeleaf y Kafka en la parte lógica para enviar un correo al cliente cuando el envío de una factura al SIAT termine con el código `908`.

1. Agregar las dependencias de JavaMail, Thymeleaf y Kafka al `pom.xml`.
2. Detectar el código `908` en la respuesta del servicio `recepcionFactura`.
3. Publicar un evento Kafka con los datos mínimos de la factura aprobada.
4. Consumir el evento y enviar el correo al cliente usando una plantilla Thymeleaf.
5. Leer las credenciales SMTP desde `recursos/gmail.md` sin exponerlas en el código ni en la configuración versionada.

## Contexto

La ODD-013 implementa el flujo completo de emisión de facturas: genera el CUF, construye y firma el XML, lo comprime, lo envía por SOAP y persiste la respuesta del SIAT en la tabla `factura`.

Después de persistir la factura, `FacturaGestionServicio.emitir` invoca el punto de extensión `notificarAprobacionSiCorresponde`. Ese punto se usa para publicar el evento de aprobación sin acoplar el envío SOAP con el envío de correo.

El repositorio contiene `recursos/gmail.md` con dos líneas:

1. Usuario Gmail.
2. Contraseña de aplicación.

Ese archivo contiene información sensible y no debe versionarse.

Kafka se usa como intermediario para que la respuesta HTTP de emisión no dependa del servidor SMTP. Si Kafka o Gmail no están disponibles, la emisión de la factura no debe fallar: el error debe registrarse y la factura debe quedar persistida con la respuesta del SIAT.

## Comprende

### Parte lógica

- Agregar dependencias de Spring Mail, Spring Thymeleaf y Spring Kafka.
- Definir propiedades de correo bajo el prefijo `correo`.
- Leer credenciales SMTP desde `recursos/gmail.md`.
- Crear un `JavaMailSenderImpl` usando Gmail SMTP con STARTTLS en el puerto `587`.
- Crear el evento `FacturaAprobadaEvento`.
- Publicar el evento después de confirmar la transacción de emisión.
- Consumir el evento desde el tópico Kafka configurado.
- Renderizar una plantilla HTML con Thymeleaf.
- Enviar el correo al `correo` registrado en `cliente`.

### No comprende

- Modificar la base de datos.
- Modificar el frontend.
- Adjuntar el XML o el PDF de la factura al correo.
- Implementar reintentos persistentes, tabla de bitácora de correos ni idempotencia de entrega.
- Cambiar los WSDL, el XSD ni el flujo de firma digital de la ODD-013.
- Enviar correos para anulación, reversión o facturas rechazadas.

## Dependencia

Esta ODD depende de:

- ODD-013: emisión SOAP, persistencia de `factura` y respuesta del SIAT.
- ODD-011: datos del cliente, incluido `correo`.
- Spring Boot 4.1.2, Java 25, MyBatis XML y Jackson 3 ya presentes.

## Decisiones

1. El correo se envía solo si `respuesta.transaccion` es `true`.
2. Se considera aprobación si `codigoEstado` es `908` o si alguno de los mensajes del SIAT tiene `codigo` `908`.
3. El código se lee desde `correo.codigo-aprobado`, con valor por defecto `908`.
4. El evento se publica después de `commit` de la transacción que persiste la factura.
5. El tópico por defecto es `sife.factura.aprobada`.
6. La clave del mensaje Kafka es el id de la factura.
7. El productor usa serialización `String`; el evento se convierte a JSON con Jackson 3.
8. El consumidor usa deserialización `String` y convierte el JSON a `FacturaAprobadaEvento` con Jackson 3.
9. Las credenciales SMTP se leen desde `recursos/gmail.md`; la ruta puede sobrescribirse con `CORREO_ARCHIVO_CREDENCIALES`.
10. Gmail se configura con `smtp.gmail.com`, puerto `587`, autenticación y STARTTLS.
11. El remitente puede sobrescribirse con `CORREO_REMITENTE`; si está vacío se usa el usuario de `gmail.md`.
12. El asunto puede sobrescribirse con `CORREO_ASUNTO`.
13. Fallos de Kafka o Gmail se registran con SLF4J; nunca se propician hacia `FacturaControlador` ni revierten la factura.
14. La plantilla HTML se ubica en `src/main/resources/templates/correo/factura-aprobada.html`.
15. `recursos/gmail.md`, `generarfirma/*.p12` y `generarfirma/*.pem` se excluyen de Git.

## Flujo

```text
FacturaControlador POST /api/v1/facturas
  -> FacturaGestionServicio.emitir
  -> SOAP recepcionFactura del SIAT
  -> persistencia de factura y detalle
  -> respuesta con codigo 908 y transaccion=true
  -> afterCommit
  -> FacturaCorreoProductor.publicar
  -> topico Kafka sife.factura.aprobada
  -> FacturaCorreoConsumidor.consumir
  -> CorreoFacturaServicio.enviar
  -> plantilla Thymeleaf
  -> JavaMailSender.send
  -> correo al cliente
```

## Contrato del evento

Tópico: `sife.factura.aprobada`

Clave: `facturaId`

Valor JSON:

```json
{
  "facturaId": 1,
  "numeroFactura": 1,
  "cuf": "8727F63A15F8976591FDDE5B387C5D015A29E06A1A19E23EF34124CD",
  "clienteNombre": "Cliente de prueba",
  "clienteCorreo": "cliente@example.com",
  "fechaEmision": "2019-01-13T16:37:21.231Z",
  "montoTotal": "99.00",
  "codigoRecepcion": "3C6D8A2B9F"
}
```

## Configuración

```yaml
spring:
  kafka:
    bootstrap-servers: ${KAFKA_BROKER:localhost:9092}
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
      properties:
        max.block.ms: 3000
        request.timeout.ms: 5000
        delivery.timeout.ms: 6000
    consumer:
      group-id: sife-factura-correo
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      auto-offset-reset: earliest

correo:
  archivo-credenciales: ${CORREO_ARCHIVO_CREDENCIALES:recursos/gmail.md}
  host: smtp.gmail.com
  puerto: 587
  remitente: ${CORREO_REMITENTE:}
  asunto: ${CORREO_ASUNTO:Factura electrónica aprobada}
  topico: ${CORREO_TOPICO:sife.factura.aprobada}
  codigo-aprobado: ${CORREO_CODIGO_APROBADO:908}
```

Variables de entorno soportadas:

| Variable | Uso |
| --- | --- |
| `CORREO_ARCHIVO_CREDENCIALES` | Ruta al archivo con usuario y contraseña de aplicación. |
| `CORREO_REMITENTE` | Remitente del correo; si está vacío se usa el usuario Gmail. |
| `CORREO_ASUNTO` | Asunto base del correo. |
| `CORREO_TOPICO` | Tópico Kafka. |
| `CORREO_CODIGO_APROBADO` | Código SIAT que dispara la notificación. |
| `KAFKA_BROKER` | Dirección del broker Kafka. |
