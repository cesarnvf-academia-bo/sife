# ODD-006: Obtención del CUIS desde el servicio Facturación Códigos

## Objetivo

Implementar en `partelogica` la operación que obtiene el CUIS de una empresa desde el servicio SOAP `FacturacionCodigos` del SIAT, enviando siempre `codigoSucursal = 0` y permitiendo únicamente los puntos de venta `0` y `1`.

## Contexto

La ODD-005 incorporó Apache CXF, la fábrica de clientes SOAP `ClienteSiatFactory`, el interceptor `InterceptorTokenApi` y el cliente generado `ServicioFacturacionCodigos`. Esa infraestructura se reutiliza en esta ODD.

La tabla `empresa` contiene los datos necesarios para construir la solicitud:

| Columna | Uso en la solicitud CUIS |
| --- | --- |
| `nit` | `nit` |
| `codigoSistema` | `codigoSistema` |
| `modalidad` | `codigoModalidad` |
| `ambiente` | `codigoAmbiente` |
| `token` | Cabecera HTTP `apiKey` |

En la base de datos actual, `modalidad` y `ambiente` almacenan códigos numéricos como texto, por ejemplo `"1"` y `"2"`. Deben convertirse a entero antes de enviarlos al SIAT.

La operación `cuis` del WSDL recibe un objeto `solicitudCuis` con estos campos:

| Campo | Tipo | Origen |
| --- | --- | --- |
| `codigoAmbiente` | `int` | `empresa.ambiente` |
| `codigoModalidad` | `int` | `empresa.modalidad` |
| `codigoPuntoVenta` | `int` nullable | Solicitud REST; solo `0` o `1` |
| `codigoSistema` | `string` | `empresa.codigoSistema` |
| `codigoSucursal` | `int` | Fijo en `0` |
| `nit` | `long` | `empresa.nit` |

El WSDL marca `codigoPuntoVenta` como opcional y lo genera como `JAXBElement<Integer>`. En esta ODD será obligatorio y se enviará mediante `ObjectFactory.createSolicitudCuisCodigoPuntoVenta(...)`.

## Comprende

- DTO de solicitud `CuisSolicitud`.
- DTO de respuesta `CuisRespuesta`.
- Servicio `ObtenerCuisServicio`.
- Controlador REST `CuisControlador`.
- Excepción para configuración SIAT inválida.
- Excepción para fallos de comunicación con el SIAT.
- Manejo HTTP de los errores anteriores.
- Pruebas del controlador y del servicio.
- Documentación Swagger del endpoint.

No comprende: CUFD, sincronización de catálogos, registro de puntos de venta, emisión de facturas, persistencia del CUIS, modificación de la tabla `empresa` ni cambios en el frontend.

## Contrato del endpoint

| Método | Ruta | Descripción |
| --- | --- | --- |
| `POST` | `/api/v1/empresas/{id}/cuis` | Obtiene el CUIS para el punto de venta indicado |

Solicitud:

```json
{
  "codigoPuntoVenta": 0
}
```

`codigoPuntoVenta` es obligatorio y solo acepta `0` o `1`. `codigoSucursal` no se recibe desde el cliente: el servicio siempre envía `0`.

Para obtener el CUIS de ambos puntos de venta se invoca el endpoint dos veces, una con `0` y otra con `1`.

Respuesta exitosa:

```json
{
  "empresaId": 1,
  "nit": "710035027",
  "codigoSucursal": 0,
  "codigoPuntoVenta": 0,
  "cuis": "A1B2C3D4E5F6",
  "fechaVigencia": "2027-05-16T23:59:59.000-04:00",
  "transaccion": true,
  "mensajes": [
    {
      "codigo": 926,
      "descripcion": "COMUNICACION EXITOSA"
    }
  ]
}
```

Estados HTTP:

| Estado | Situación |
| --- | --- |
| `200` | El SIAT respondió, aunque `transaccion` sea `false` |
| `400` | `codigoPuntoVenta` ausente o fuera de `0` y `1` |
| `404` | La empresa no existe |
| `409` | La empresa no tiene token o su configuración SIAT es inválida |
| `502` | Error de conexión, timeout o fallo SOAP al invocar el SIAT |

## Implementación

### 1. Reutilizar el cliente de Facturación Códigos

No se agregan dependencias ni WSDL. Se usa la interfaz generada:

```java
bo.gob.impuesto.siat.codigos.ServicioFacturacionCodigos
```

La operación generada es:

```java
RespuestaCuis cuis(SolicitudCuis solicitudCuis);
```

El puerto se crea con `ClienteSiatFactory.crearPuerto(...)`, usando `propiedades.codigosUrl()` y el token de la empresa. La cabecera `apiKey: TokenApi <token>` la agrega automáticamente `InterceptorTokenApi`.

### 2. Crear el DTO de solicitud

Crear `CuisSolicitud`:

```java
public record CuisSolicitud(
        @NotNull(message = "El punto de venta es obligatorio.")
        @Min(value = 0, message = "El punto de venta debe ser 0 o 1.")
        @Max(value = 1, message = "El punto de venta debe ser 0 o 1.")
        Integer codigoPuntoVenta) {
}
```

El controlador debe usar `@Valid` para que `ManejadorErrores` transforme las violaciones en `400 Bad Request`.

### 3. Crear el DTO de respuesta

Crear `CuisRespuesta`:

```java
public record CuisRespuesta(
        Long empresaId,
        String nit,
        int codigoSucursal,
        int codigoPuntoVenta,
        String cuis,
        String fechaVigencia,
        boolean transaccion,
        List<MensajeCuis> mensajes) {

    public record MensajeCuis(Integer codigo, String descripcion) {
    }
}
```

`fechaVigencia` se obtiene con `XMLGregorianCalendar.toXMLFormat()`. No se realizan conversiones de zona horaria.

### 4. Crear el servicio

Crear `ObtenerCuisServicio`:

```java
@Service
@RequiredArgsConstructor
public class ObtenerCuisServicio {

    private static final int CODIGO_SUCURSAL = 0;

    private final EmpresaRepositorio empresaRepositorio;
    private final ClienteSiatFactory clienteSiatFactory;
    private final PropiedadesSiat propiedades;

    public CuisRespuesta obtener(Long empresaId, CuisSolicitud solicitud) {
        Empresa empresa = empresaRepositorio.findById(empresaId)
                .orElseThrow(() -> new EmpresaNoEncontradaExcepcion(empresaId));

        if (empresa.getToken() == null || empresa.getToken().isBlank()) {
            throw new TokenSiatNoConfiguradoExcepcion(empresaId);
        }

        String codigoSistema = empresa.getCodigoSistema();
        if (codigoSistema == null || codigoSistema.isBlank()) {
            throw new ConfiguracionSiatInvalidaExcepcion(empresaId, "codigoSistema");
        }

        int codigoAmbiente = parsearEntero(
                empresaId, "ambiente", empresa.getAmbiente());
        int codigoModalidad = parsearEntero(
                empresaId, "modalidad", empresa.getModalidad());
        long nit = parsearNit(empresaId, empresa.getNit());
        int codigoPuntoVenta = solicitud.codigoPuntoVenta();

        SolicitudCuis solicitudSiat = new SolicitudCuis();
        solicitudSiat.setCodigoAmbiente(codigoAmbiente);
        solicitudSiat.setCodigoModalidad(codigoModalidad);
        solicitudSiat.setCodigoSistema(codigoSistema);
        solicitudSiat.setCodigoSucursal(CODIGO_SUCURSAL);
        solicitudSiat.setNit(nit);
        solicitudSiat.setCodigoPuntoVenta(new ObjectFactory()
                .createSolicitudCuisCodigoPuntoVenta(codigoPuntoVenta));

        try {
            RespuestaCuis respuesta = clienteSiatFactory
                    .crearPuerto(
                            ServicioFacturacionCodigos.class,
                            propiedades.codigosUrl(),
                            empresa.getToken().trim())
                    .cuis(solicitudSiat);

            return new CuisRespuesta(
                    empresa.getId(),
                    empresa.getNit(),
                    CODIGO_SUCURSAL,
                    codigoPuntoVenta,
                    respuesta.getCodigo(),
                    respuesta.getFechaVigencia() == null
                            ? null
                            : respuesta.getFechaVigencia().toXMLFormat(),
                    Boolean.TRUE.equals(respuesta.isTransaccion()),
                    respuesta.getMensajesList().stream()
                            .map(mensaje -> new CuisRespuesta.MensajeCuis(
                                    mensaje.getCodigo(),
                                    mensaje.getDescripcion()))
                            .toList());
        } catch (Exception excepcion) {
            throw new SiatNoDisponibleExcepcion(
                    "FacturacionCodigos", mensajeError(excepcion));
        }
    }

    private int parsearEntero(Long empresaId, String campo, String valor) {
        try {
            return Integer.parseInt(valor);
        } catch (NumberFormatException excepcion) {
            throw new ConfiguracionSiatInvalidaExcepcion(empresaId, campo);
        }
    }

    private long parsearNit(Long empresaId, String nit) {
        try {
            return Long.parseLong(nit);
        } catch (NumberFormatException excepcion) {
            throw new ConfiguracionSiatInvalidaExcepcion(empresaId, "nit");
        }
    }

    private String mensajeError(Exception excepcion) {
        String mensaje = excepcion.getMessage();
        return mensaje == null || mensaje.isBlank()
                ? excepcion.getClass().getSimpleName()
                : mensaje;
    }
}
```

Reglas del servicio:

1. Buscar la empresa por `id`.
2. Rechazar empresas sin token.
3. Validar `codigoSistema`, `nit`, `ambiente` y `modalidad`.
4. Enviar siempre `codigoSucursal = 0`.
5. Enviar el `codigoPuntoVenta` recibido, que ya fue validado como `0` o `1`.
6. Mapear `RespuestaCuis` al DTO de respuesta.
7. No persistir el CUIS ni abrir transacciones de base de datos durante la llamada SOAP.

### 5. Crear el controlador

Crear `CuisControlador` en `bo.org.citior.sife.controlador`:

```java
@RestController
@RequestMapping("/api/v1/empresas/{id}/cuis")
@RequiredArgsConstructor
@Tag(name = "CUIS", description = "Obtención del CUIS desde el SIAT")
public class CuisControlador {

    private final ObtenerCuisServicio obtenerCuisServicio;

    @PostMapping
    @Operation(
            summary = "Obtener CUIS",
            description = "Obtiene el CUIS para la sucursal 0 y el punto de venta indicado.")
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Respuesta del SIAT"),
            @ApiResponse(responseCode = "400", description = "Punto de venta inválido"),
            @ApiResponse(responseCode = "404", description = "Empresa no encontrada"),
            @ApiResponse(responseCode = "409", description = "Token o configuración SIAT inválida"),
            @ApiResponse(responseCode = "502", description = "Servicio SIAT no disponible")
    })
    public ResponseEntity<CuisRespuesta> obtener(
            @PathVariable Long id,
            @Valid @RequestBody CuisSolicitud solicitud) {

        return ResponseEntity.ok(obtenerCuisServicio.obtener(id, solicitud));
    }
}
```

### 6. Agregar el manejo de errores

Crear `ConfiguracionSiatInvalidaExcepcion`:

```java
public class ConfiguracionSiatInvalidaExcepcion extends RuntimeException {

    private final Long empresaId;
    private final String campo;

    public ConfiguracionSiatInvalidaExcepcion(Long empresaId, String campo) {
        super("La empresa " + empresaId
                + " tiene un valor inválido o ausente en '" + campo + "'.");
        this.empresaId = empresaId;
        this.campo = campo;
    }

    public Long getEmpresaId() {
        return empresaId;
    }

    public String getCampo() {
        return campo;
    }
}
```

Crear `SiatNoDisponibleExcepcion`:

```java
public class SiatNoDisponibleExcepcion extends RuntimeException {

    private final String servicio;

    public SiatNoDisponibleExcepcion(String servicio, String detalle) {
        super("No se pudo obtener el CUIS del servicio "
                + servicio + ": " + detalle);
        this.servicio = servicio;
    }

    public String getServicio() {
        return servicio;
    }
}
```

Agregar en `ManejadorErrores`:

```java
@ExceptionHandler(ConfiguracionSiatInvalidaExcepcion.class)
public ProblemDetail manejarConfiguracionSiatInvalida(
        ConfiguracionSiatInvalidaExcepcion excepcion) {

    ProblemDetail problema = ProblemDetail.forStatusAndDetail(
            HttpStatus.CONFLICT, excepcion.getMessage());
    problema.setTitle("Configuración SIAT inválida");
    problema.setProperty("empresaId", excepcion.getEmpresaId());
    problema.setProperty("campo", excepcion.getCampo());
    return problema;
}

@ExceptionHandler(SiatNoDisponibleExcepcion.class)
public ProblemDetail manejarSiatNoDisponible(SiatNoDisponibleExcepcion excepcion) {
    ProblemDetail problema = ProblemDetail.forStatusAndDetail(
            HttpStatus.BAD_GATEWAY, excepcion.getMessage());
    problema.setTitle("Servicio SIAT no disponible");
    problema.setProperty("servicio", excepcion.getServicio());
    return problema;
}
```

El `400` por punto de venta inválido ya lo maneja el método existente `manejarSolicitudInvalida`.

## Criterios de Aceptación

- [ ] El endpoint `POST /api/v1/empresas/{id}/cuis` está disponible.
- [ ] El servicio envía siempre `codigoSucursal = 0`.
- [ ] Solo se aceptan los puntos de venta `0` y `1`.
- [ ] Un punto de venta inválido responde `400`.
- [ ] `codigoAmbiente`, `codigoModalidad`, `codigoSistema` y `nit` se toman de la empresa.
- [ ] El token se envía mediante la cabecera `apiKey: TokenApi <token>`.
- [ ] La respuesta incluye `cuis`, `fechaVigencia`, `transaccion` y `mensajes`.
- [ ] Una empresa inexistente responde `404`.
- [ ] Una empresa sin token o con configuración inválida responde `409`.
- [ ] Un fallo de comunicación con el SIAT responde `502`.
- [ ] El token no aparece en respuestas ni logs.
- [ ] La compilación y las pruebas finalizan sin errores.

## Confirmación y cierre

La ODD se considera completada cuando:

- El endpoint obtiene el CUIS desde `FacturacionCodigos`.
- La solicitud envía `codigoSucursal = 0`.
- Los únicos puntos de venta aceptados son `0` y `1`.
- Los datos de la empresa se envían correctamente.
- Los errores `400`, `404`, `409` y `502` están cubiertos.
- El token no se expone.
- La compilación y las pruebas pasan.
- El responsable técnico revisa y aprueba el entregable, dejando constancia del cierre de la ODD-006.
