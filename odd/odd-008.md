# ODD-008: Eliminación de JPA, persistencia con MyBatis XML, empresa única, normalización de columnas y CRUD de Sucursal

## Objetivo

Eliminar Spring Data JPA y migrar la persistencia de `partelogica` a MyBatis con mapeo XML, normalizar los nombres de columnas de `tablas.sql` a `snake_case`, garantizar que en `empresa` exista un único registro con `id = 1L`, ajustar la pantalla de Empresa en la parte visual y crear el CRUD completo de `sucursal` en `partelogica` y `partevisual`.

## Contexto

Las ODD-004, ODD-006 y ODD-007 dejaron funcionando el modelo `Empresa`, el repositorio JPA, los servicios CUIS/CUFD y la pantalla Empresa. Según la aclaración de esta ODD, **se elimina JPA** y **la persistencia se realiza con MyBatis usando archivos XML**. No se conservan `JpaRepository`, `EntityManager`, entidades `@Entity` ni anotaciones `jakarta.persistence`.

La tabla `empresa` fue creada con identificadores en camelCase y algunos nombres entre comillas, por ejemplo `"codigoSistema"` y `"rutacodigo"`. En esta ODD todos los identificadores de `tablas.sql` pasan a `snake_case`: `codigoSistema` → `codigo_sistema`, `razonsocial` → `razon_social`, `rutacodigo` → `ruta_codigo`, y así sucesivamente.

La empresa será un único registro fijo con `id = 1L`. Ya no se generará el identificador automáticamente. La operación de adicionar debe comportarse como *upsert*: si el registro `1L` existe, se redirige a la modificación; si no existe, se inserta con `id = 1L`.

La pantalla Empresa debe dejar de mostrar solo dos columnas fijas: los campos se distribuyen según el ancho del dato. Además, debe existir un único botón **Actualizar**, con su icono.

Se agrega el modelo `sucursal(id, codigo, sucursal, estado)` con CRUD en la API REST y una pantalla en Angular con buscador, paginación, tabla de acciones y botones con iconos representativos.

## Comprende

**Parte lógica:**

- Eliminación de Spring Data JPA, Hibernate y anotaciones JPA.

- Cambios en `EmpresaMapper`, `EmpresaServicio`, DTO, mapeador y modelo.
- Comportamiento *upsert* en `adicionar`.
- Modelo `Sucursal`, `SucursalMapper`, DTOs, mapeador, servicio y controlador.
- Paginación construida en el servicio a partir de consultas MyBatis.
- Validaciones, manejo de errores y documentación Swagger.
- Pruebas unitarias y de controlador.

**Parte visual:**

- Ajuste del formulario de Empresa para usar el ancho del dato.
- Un único botón **Actualizar** en Empresa.
- Opción **Sucursal** en el menú lateral.
- Ruta `/sucursal` y migas de pan `Inicio > Sucursal` alineadas a la izquierda.

## Modelo de datos

### `basededatos/tablas.sql`

Reemplazar el contenido por:

```sql
CREATE TABLE empresa (
    id BIGINT PRIMARY KEY,
    nit VARCHAR(20),
    razon_social VARCHAR(250),
    codigo_sistema VARCHAR(50),
    modalidad VARCHAR(50),
    ambiente VARCHAR(50),
    ruta_codigo TEXT,
    ruta_sincronizacion TEXT,
    ruta_operacion TEXT,
    ruta_compraventa TEXT,
    token TEXT,
    ruta_firma_digital TEXT,
    clave_firma_digital TEXT
);

CREATE TABLE sucursal (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    codigo VARCHAR(20) NOT NULL UNIQUE,
    sucursal VARCHAR(250) NOT NULL,
    estado BOOLEAN NOT NULL DEFAULT TRUE
);
```

Reglas:

1. Todos los identificadores de `tablas.sql` usan `snake_case`.
2. `empresa.id` ya no es `IDENTITY`; se fija manualmente en `1L`.
3. `sucursal.id` mantiene generación automática.
4. `sucursal.codigo` es obligatorio y único.
5. `sucursal.estado` es obligatorio y por defecto `TRUE`.
6. `datos.sql` debe dejar como máximo un registro en `empresa`, con `id = 1`.

### Cambio de `empresa` y actualización de campos

La definición anterior de `empresa` usaba `id BIGINT GENERATED ALWAYS AS IDENTITY`, identificadores camelCase y nombres entre comillas. Esa definición se reemplaza en `basededatos/tablas.sql` y el cambio se propaga a `partelogica` y `partevisual`.

**Actualizaciones en `partelogica`:**

- `Empresa.java` deja de ser entidad JPA y usa los nombres Java de la tabla anterior.
- `EmpresaMapper.xml` usa las columnas nuevas en `SELECT`, `INSERT` y `UPDATE`.

**Actualizaciones en `partevisual`:**

- `modelos/empresa.ts` conserva `razonsocial` y aplica los demás nombres de la columna TypeScript de la tabla anterior.
- `paginas/empresa/empresa.ts` actualiza los controles del formulario reactivo.

- No se modifica el contrato JSON de la API.

### Configuración MyBatis

Eliminar toda la sección `spring.jpa`. La configuración queda:

```yaml
spring:
  datasource:
    url: ${BD_URL:jdbc:postgresql://localhost:5432/sife}
    username: ${BD_USUARIO:postgres}
    password: ${BD_CLAVE:}

mybatis:
  mapper-locations: classpath*:mapper/**/*.xml
  type-aliases-package: bo.org.citior.sife.dominio
  configuration:
    map-underscore-to-camel-case: true
```

`map-underscore-to-camel-case` permite mapear `codigo_sistema` → `codigoSistema`, `ruta_codigo` → `rutaCodigo` y así sucesivamente. La excepción es `razon_social`: como Java/JSON conserva `razonsocial`, el `SELECT` de `EmpresaMapper.xml` debe usar `razon_social AS razonsocial`.

### 4. Ajustar `EmpresaServicio`

Agregar `ResultadoOperacionEmpresa`:

```java
public record ResultadoOperacionEmpresa(EmpresaRespuesta respuesta, boolean creado) {
}
```

Ajustar el servicio:

```java
public static final Long EMPRESA_ID = 1L;

@Transactional
public ResultadoOperacionEmpresa adicionar(EmpresaSolicitud solicitud) {
    Empresa existente = empresaMapper.findById(EMPRESA_ID);
    if (existente != null) {
        return new ResultadoOperacionEmpresa(modificar(EMPRESA_ID, solicitud), false);
    }

    Empresa empresa = empresaMapeador.aModelo(solicitud);
    empresa.setId(EMPRESA_ID);
    empresaMapper.insert(empresa);
    return new ResultadoOperacionEmpresa(empresaMapeador.aRespuesta(empresa), true);
}

@Transactional
public EmpresaRespuesta modificar(Long id, EmpresaSolicitud solicitud) {
    Empresa empresa = empresaMapper.findById(id);
    if (empresa == null) {
        throw new EmpresaNoEncontradaExcepcion(id);
    }

    empresaMapeador.actualizar(empresa, solicitud);
    empresaMapper.update(empresa);
    return empresaMapeador.aRespuesta(empresa);
}
```

Reglas:

1. `POST /api/v1/empresas` busca siempre `id = 1L` con `EmpresaMapper.findById`.
2. Si existe, ejecuta la lógica de `modificar(1L, solicitud)` y responde `200 OK`.
3. Si no existe, inserta con `id = 1L` y responde `201 Created`.
4. `PUT /api/v1/empresas/1` sigue modificando el registro existente.
5. `GET /api/v1/empresas/1` obtiene el registro con `EmpresaMapper.findById`.
6. No se permite crear empresas con otro identificador.
7. La respuesta sigue sin exponer `token` ni `claveFirmaDigital`.
8. El `<set>` dinámico del XML conserva los valores sensibles cuando llegan nulos o vacíos.

Contrato de `POST /api/v1/empresas` en `EmpresaControlador`:

```java
ResultadoOperacionEmpresa resultado = empresaServicio.adicionar(solicitud);
return resultado.creado()
        ? ResponseEntity.created(URI.create("/api/v1/empresas/" + resultado.respuesta().id()))
                .body(resultado.respuesta())
        : ResponseEntity.ok(resultado.respuesta());
```

En Swagger documentar `200 OK` para "Empresa modificada" y `201 Created` para "Empresa creada".

### 7. Crear `SucursalMapper`

```java
@Mapper
public interface SucursalMapper {

    Sucursal findById(@Param("id") Long id);

    List<Sucursal> listar(
            @Param("busqueda") String busqueda,
            @Param("offset") int offset,
            @Param("size") int size);

    boolean existsByCodigo(@Param("codigo") String codigo);

    boolean existsByCodigoAndIdNot(
            @Param("codigo") String codigo,
```

`partelogica/src/main/resources/mapper/SucursalMapper.xml`:

```xml
<mapper namespace="bo.org.citior.sife.mapper.SucursalMapper">

  <sql id="filtro">
    <if test="busqueda != null and busqueda != ''">
      AND (LOWER(codigo) LIKE LOWER(CONCAT('%', #{busqueda}, '%'))
        OR LOWER(sucursal) LIKE LOWER(CONCAT('%', #{busqueda}, '%')))
    </if>
  </sql>

  <select id="findById" resultType="bo.org.citior.sife.dominio.Sucursal">
    SELECT id, codigo, sucursal, estado
    FROM sucursal
    WHERE id = #{id}
  </select>

  <select id="listar" resultType="bo.org.citior.sife.dominio.Sucursal">
    SELECT id, codigo, sucursal, estado
    FROM sucursal
    WHERE 1 = 1
    <include refid="filtro" />
    ORDER BY id
    LIMIT #{size} OFFSET #{offset}
  </select>

  <select id="contar" resultType="long">
    SELECT COUNT(*)
    FROM sucursal
    WHERE 1 = 1
    <include refid="filtro" />
  </select>

  <select id="existsByCodigo" resultType="boolean">
    SELECT EXISTS (SELECT 1 FROM sucursal WHERE codigo = #{codigo})
  </select>

  <select id="existsByCodigoAndIdNot" resultType="boolean">
    SELECT EXISTS (
      SELECT 1 FROM sucursal
      WHERE codigo = #{codigo} AND id <> #{id}
    )
  </select>

  <insert id="insert"
          parameterType="bo.org.citior.sife.dominio.Sucursal"
          useGeneratedKeys="true"
          keyProperty="id">
    INSERT INTO sucursal (codigo, sucursal, estado)
    VALUES (#{codigo}, #{sucursal}, #{estado})
  </insert>

  <update id="update" parameterType="bo.org.citior.sife.dominio.Sucursal">
    UPDATE sucursal
    SET codigo = #{codigo},
        sucursal = #{sucursal},
        estado = #{estado}
    WHERE id = #{id}
  </update>

  <delete id="delete">
    DELETE FROM sucursal WHERE id = #{id}
  </delete>

</mapper>
```

### 8. Crear `SucursalServicio`

Métodos:

```java
PaginaRespuesta<SucursalRespuesta> listar(String busqueda, int page, int size);

SucursalRespuesta obtenerPorId(Long id);

SucursalRespuesta adicionar(SucursalSolicitud solicitud);

SucursalRespuesta modificar(Long id, SucursalSolicitud solicitud);

void eliminar(Long id);
```

Reglas:

1. La búsqueda se aplica a `codigo` y `sucursal` con `LIKE %texto%`, sin distinguir mayúsculas.
2. El `offset` se calcula con `page * size`.
3. `totalElements` se obtiene con `SucursalMapper.contar`.
4. `totalPages` se calcula con `(int) Math.ceil((double) totalElements / size)`.
5. `size` se valida en el controlador: solo `5`, `10`, `15` o `20`.
6. `codigo` duplicado al adicionar o modificar lanza `SucursalCodigoDuplicadoExcepcion` → `409 Conflict`.
7. Una sucursal inexistente lanza `SucursalNoEncontradaExcepcion` → `404 Not Found`.
8. Datos inválidos responden `400 Bad Request`.
9. Toda la persistencia se realiza mediante `SucursalMapper` y su XML.
10. No se usa `JpaRepository`, `EntityManager` ni SQL embebido en Java.

| Parámetro | Ejemplo | Descripción |

| `busqueda` | `LP` | Filtro sobre `codigo` o `sucursal` |
| `page` | `0` | Página basada en cero |
| `size` | `5` | Tamaño permitido: `5`, `10`, `15` o `20` |
